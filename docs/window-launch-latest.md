# 应用启动自动最大化已撤销

0.8.58 / controller 0.3.22。用户于 2026-10-18 明确要求：“最大化的所有修改全部撤掉吧，默认是咋样就咋样”。这覆盖并撤销此前所有全局新窗口最大化、三种入口限定最大化和系统应用识别修补要求。

## 当前行为

LeanDock 不再识别应用启动、不跟踪新建窗口以决定最大化，也不发送最大化或还原动作。开始菜单单击、Dock 应用图标单击、快捷方式双击、其他入口、后台启动和已有窗口，均按应用与 Windows 原生行为处理。

原功能未写入应用尺寸配置、快捷方式显示命令或注册表；没有相关独立计划任务。当前窗口状态不被主动还原。应用若自行记住上次最大化状态，后续仍可能最大化，这是其原生行为，不能为了强制普通窗口再加一套干预。

## 完整移除范围

- 控制器对启动模块的包含、启动、消息分发、退出和状态字段。
- 专用窗口事件监听、一次性候选和计时、窗口所有权标记、启动目标识别、只读 UI Automation 工作线程和鼠标预取。
- 自动最大化提交代码、三个功能头文件及专属测试入口/产物。原实现连同许可证出处另行保存在回退材料，不作为运行或构建入口。
- 正式部署中遗留的同名源码/测试文件在新控制器生效后按逐文件哈希核对退役；退役列表和恢复副本单独保存。

旧控制器通过现有 Stop 流程取消候选、停止工作线程、注销专用事件并清除自己持有的窗口标记，再加载不含该功能的新控制器。原生鼠标注册仍由触发角组件持有，不被移除。

## 保留的独立功能

Ctrl＋Alt＋Tab 0.8.57 的预览尺寸、布局与交互保留；Dock 和触发角在已有最大化应用前仍可正常唤出。相关的最大化/全屏状态检测属于隐藏和唤出逻辑，不会把应用放大，不能按“最大化”字样误删。原生 Dock、卡片、托盘、开始菜单紧凑与快速设置不在本次撤销范围。

## 证据与回退

当前控制器编译成功；129 项触发角核心与 32 项配置检查通过，未注册或模拟桌面输入。新二进制不含旧版存在的 ShowWindowAsync 导入名、功能模式、状态字段和所有权标记；源代码无剩余启动模块调用。三个宿主 DLL 哈希与 0.8.57 一致。

最终部署版本、原标记清理、四组件恢复、配置一致性与未验证范围见 verification-latest.json。旧功能源码、测试及旧说明已保存在本任务 outputs/remove-launch-maximize-20261018/before；上游参考和许可证保留作历史归属。使用既有更新和回退流程，不改系统防护、用户应用设置或快捷方式，不提交或推送。
