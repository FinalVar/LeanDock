# LeanDock 维护交接

## 当前基线

项目 0.7.1；控制程序 0.3.4；Explorer 组件 0.4.14；开始菜单组件 0.1.3；快速设置组件 0.2.1。

本页较早的版本段落是演进记录。当前功能以 README、docs/verification-latest.json
和正式部署收据为准。0.7.1 的来源复核、退出保护修正以及尚未验证的边界见
docs/reuse-audit-latest.md；统一更新、回退入口见 docs/maintenance-latest.md。

配置：应用图像 40、按钮宽 52、任务栏高 64、背景高 60、底边留白 4 DIP；小图标 24×24、列距 28。应用与托盘用 1×40 DIP 柔和竖线分开。连续两排、末列单颗上下居中的布局保持。

0.3.1 取消应用按钮白色描边，将活动／悬停背景改为低透明度纯色，并减弱 Dock 外沿高光。`MultiWindowElement` 仅设 `Opacity=0`、`IsHitTestVisible=False`，不折叠或更改其布局尺寸，避免影响原生多窗口裁剪、分组和预览。生成器按配置中的目标条目生成规则，新增样式不再依赖手动修改固定数量。控制程序、触发角配置、托盘排列和范围计算代码未修改。

0.3.2 应用户要求，将 `src/surface-latest.inc` 中竖线的高度由 28 调整为 40 DIP。功能性修改仅此一项；仍宽 1 DIP、垂直居中、使用原渐变，并保持不可点击。

0.3.3 将开始菜单的原生 AllAppsGrid 分组内容平铺到不分组的 CollectionViewSource.View，保留原生应用与文件夹对象及点击处理。ViewSelectionButton 隐藏、禁用并移出 Tab 顺序；SemanticZoom 的字母跳转关闭。停用时恢复数据绑定、原始集合、分组样式与入口属性。不修改菜单尺寸、搜索、应用图像、固定区、推荐区和 Windows 缩放。

0.3.4 在连续网格基础上收紧原生菜单外框：隐藏 AllListHeading，清除高度为零的固定区残留边距，并给应用区保留 12 DIP 顶部留白。根据真实原生单元格尺寸、应用数量、原生列数上限和显示器可用宽度选择列数；保持最少行数后收掉多余列。高度包含应用行、原生搜索与底栏、有效标题内容和原有边距，并受系统 MaxHeight 与工作区限制；超出时仍由原生控件滚动。当前 41 项为 7 列、6 行，面板由约 834×866 缩到 738×670 DIP，图标与文字未缩放。

尺寸不能依赖 MainMenu 首次出现时的 Width：Windows 有时先给出临时 642 DIP，再完成响应式布局。列数以原生 ItemsWrapGrid.MaximumRowsOrColumns 为上限，避免停用再启用后变成不同列数。被修改的依赖属性保存原本地值、有效值和数据绑定；停用时恢复。若原生属性后来被外部更新，下一次覆盖前保留其最新值。只处理已匹配的本机模板；存在有高度的固定区时退回原生尺寸。安装卸载应用、显示器或辅助功能变化仍须真实场景验证。

早期 0.1.0 预览在用户确认排列与应用／文件夹点击正常之后发生过 Start 宿主崩溃（E_NOINTERFACE），用户同时报告曾切换类别／网格／列表；没有转储堆栈证明直接因果。该版没有接入自启。0.1.1 保留原生 ICollectionView 契约并锁定切换入口，必须以新版本的运行和界面证据验收，不能用此前反馈覆盖后续回归。

## 代码入口

| 位置 | 职责 |
| --- | --- |
| `build/generate-latest.py` | 根据保留的上游源码和固定配置生成任务栏适配 |
| `build/adapt-hotcorners-latest.py` | 把原有触发角实现接入控制程序 |
| `include/dock-geometry-latest.h`、`include/shell-panels-latest.h` | 投影 Dock 范围、原生菜单定位和有限窗口事件 |
| `src/surface-latest.inc` | Explorer XAML 的短分隔线，随组件停止移除 |
| `src/controller-latest.cpp` | 系统核验、隐藏控制窗口、Explorer 生命周期、触发角消息循环 |
| `src/runtime-latest.cpp` | 组件管理、共享钩子链、还原和运行状态 |
| `src/tray-latest.cpp` | 生成的连续托盘布局 |
| `src/start-layout-latest.cpp`、`include/start-host-latest.h` | 原生开始菜单连续网格、切换入口锁定、独立宿主校验和恢复 |

| `baseline/` | 外观、固定功能参数、系统组件哈希、符号缓存 |
| `hotcorners/core/`、`hotcorners/actions/` | 触发状态机和系统按键序列 |

保留的 `upstream/tray.cpp` 已包含本地 1.4.2 网格改动。其余来源关系和许可证在 NOTICE 中；不要将本地派生输入误称为未经修改的官方版本。

## 更新与回归

1. 核对正在维护的完整部署路径、当前版本、源文件和配置哈希。
2. 在源码目录改生成器或对应原生模块，重新生成／构建。运行与改动相关的检查。
3. 部署前单独保存旧二进制、配置、管理脚本、任务 XML 和收据，准备可恢复旧映像的保护流程。
4. 正常 Stop 后等待还原；在当前用户会话中核对精确 Explorer 路径，再干净重载并启动。不能将一个项目的历史自动回退脚本套用于未知版本。
5. 对照真实界面验证图标、悬停、点击和当前修改涉及的行为。状态文件与动作计数不能代替界面验收。

系统更新造成哈希或符号不匹配时停止旧组件附加，重新审核系统结构。没有兼容性证据时，不通过删除校验或猜测偏移继续运行。

## 已知维护事项

- 当前控制程序使用同用户 HighestAvailable 任务，支持管理员前台应用下的触发角。保留有限的管理消息白名单，不增加任意命令执行入口。
- 历史任务更新曾遇到 CIM 将 SID 改写为短用户名导致注册失败；需要修改已有 Principal 时优先保留导出 XML 中的完整 SID。
- 本次核验的生产配置为左上停留 500 毫秒锁屏，底部两角零停留、零冷却；离开 32 像素区域是重新触发条件，不是等待时间。后续更新保留实际配置，不用旧记录覆盖。
- 运行时仍使用 NativeTaskbarDock / NativeHotCorners 内部标识。未来重命名需要独立迁移设计，不能只改一处名称。
- 0.3.0 将低浓度模糊背景、反光和渐变边缘组合为玻璃质感；这不包含 KWin 的 Snell 折射。
- 开启保留 Styler 的窗口区域裁剪，并在现有 WndProc 中过滤 Dock 宽度以外的鼠标悬停计时器。保留键盘、无障碍和菜单主动 Unhide 请求。几何来自已布局 XAML 根、转换为当前窗口的物理像素，不随隐藏动画改变投影范围。
- 开始菜单与快速设置分别加载组件，在所属 UI 线程的 WM_WINDOWPOSCHANGING 中调整待提交坐标；控制程序的窗口事件用于发现宿主，不再事后搬动窗口。快速设置组件同时承载主题磁贴适配。StartMenuExperienceHost.exe 与 StartDocked.dll 的 SHA-256 都需匹配，失败只禁用开始菜单布局，不影响触发角和兼容的 Dock。
- 开始菜单关闭或被系统暂停时等待 SHOW／UNCLOAKED 事件，不持续轮询。每个宿主只尝试附加一次，修改后的宿主退出时停止本次会话的再次附加，避免崩溃循环。控制程序正常停止或意外退出会请求还原；开始菜单组件保留映射直到该系统进程退出，以保证回调地址有效。
- 状态必须核对实际 PID、进程路径、已加载组件和当前控制程序归属；磁盘旧状态不代表新宿主已修改。`StartLayoutReady` 与 Dock／触发角就绪分别报告，开始菜单尚未展开时不阻塞控制程序启动。
- 触发角左上为 lock-screen，其余配置保留。锁屏 API 成功只表示请求获接收，真实锁定效果须用户观察。
- 一次维护发现同会话同时存在多个 Explorer；维护入口已改为核对 Shell_TrayWnd 的所属 PID 和完整路径，不能再以“只有一个 explorer.exe”作为前提。
