# LeanDock 维护交接

## 当前基线

项目 0.2.3；控制程序 0.2.1；Explorer 组件 0.1.2。源码首次入库沿用正在使用的运行实现，仓库整理只调整构建／测试入口、管理脚本的可移植范围和文档。生产程序、任务和用户配置不随 Git 操作变化。

配置：应用图像 32、按钮宽 44、任务栏高 56、背景高 52、底边留白 4；小图标 24×24，列距 28。应用托盘后接电池；输入法不计数。末列孤立图标在两排高度中央，其原生按钮整体平移，因此图像和鼠标区域同向移动。

## 代码入口

| 位置 | 职责 |
| --- | --- |
| `build/generate-latest.py` | 根据保留的上游源码和固定配置生成任务栏适配 |
| `build/adapt-hotcorners-latest.py` | 把原有触发角实现接入控制程序 |
| `src/controller-latest.cpp` | 系统核验、隐藏控制窗口、Explorer 生命周期、触发角消息循环 |
| `src/runtime-latest.cpp` | 组件管理、共享钩子链、还原和运行状态 |
| `src/tray-latest.cpp` | 生成的连续托盘布局 |
| `baseline/` | 外观、固定功能参数、系统组件哈希、符号缓存 |
| `hotcorners/core/`、`hotcorners/actions/` | 触发状态机和系统按键序列 |

保留的 `upstream/tray.cpp` 已包含本地 1.4.2 网格改动。其余来源关系和许可证在 NOTICE 中；不要将本地派生输入误称为未经修改的官方版本。

## 更新与回归

1. 核对正在维护的完整部署路径、当前版本、源文件和配置哈希。
2. 在源码目录改生成器或对应原生模块，重新生成／构建。运行与改动相关的检查。
3. 部署前单独保存旧二进制、配置、管理脚本、任务 XML 和收据，准备可恢复旧映像的保护流程。
4. 正常 Stop 后等待还原；在当前用户会话中核对精确 Explorer 路径，再干净重载并启动。不能将一个项目的历史自动回退脚本套用于未知版本。
5. 对照真实界面验证图标、悬停、点击和当前修改涉及的行为。状态文件与动作计数不能代替界面验收。

系统更新造成哈希或符号不匹配时停止旧组件附加，重新审核系统结构。没有兼容性证据时，不通过删除校验或猜测偏移继续运行。

## 已知维护事项

- 当前控制程序使用同用户 HighestAvailable 任务，支持管理员前台应用下的触发角。保留有限的管理消息白名单，不增加任意命令执行入口。
- 历史任务更新曾遇到 CIM 将 SID 改写为短用户名导致注册失败；需要修改已有 Principal 时优先保留导出 XML 中的完整 SID。
- 生产配置默认零停留、零冷却；离开 32 像素区域是重新触发条件，不是等待时间。
- 运行时仍使用 NativeTaskbarDock / NativeHotCorners 内部标识。未来重命名需要独立迁移设计，不能只改一处名称。
- 用户已要求下一步参考 NextKDE 优化液态玻璃、开始菜单与快速设置／电源菜单位置，以及按 Dock 实际宽度限制呼出。本基线尚未包含这些改动。
