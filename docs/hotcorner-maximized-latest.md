# GPT 最大化时触发角偶发失效

适用版本：0.8.28 / controller 0.3.12 / hotcorners 1.0.4-integrated。

## 已确认与推断

用户明确指左下返回桌面、右下任务视图，区别于 Dock 底边唤出。2026-10-13 的修复前只读状态显示控制器仍在运行、原始输入和判断次数持续增加、动作提交失败为零，已有 19 次保护拦截。旧状态未细分拦截原因，不能将这 19 次全部认定为全屏误判。

当前 GPT 包为 OpenAI.Codex_2p2nqsd0c76g0，窗口原生 IsZoomed=true、WS_THICKFRAME 存在、无 WS_CAPTION，窗口矩形覆盖 2560×1600 显示器。当次 DWM 可见边界底部是 1598，旧规则当时不拦截。旧代码在同一最大化窗口的可见边界覆盖屏幕时会判定全屏；此分支错误已用回归复现，但未在修改前抓到用户那次失败的原始边界。不得把推断写成全部偶发失败已解释。

## 修正与维护边界

继续保留 NativeHotCorners 原始输入、动作与空间重新触发逻辑；修改接入生成器，生成 src/hotcorners-latest.cpp。提取既有 GPT 底边适配的只读客户端身份核验供两个入口共用，包家族、可执行文件后缀、窗口类三个条件均须满足。仅当原生最大化且保留可调整大小边框时豁免全屏抑制，不依赖稍后才设置的 NonRudeHWND，不调整窗口、桌面焦点或任务栏状态。

其他程序及身份核验失败仍使用原有全屏保护；GPT 退出最大化或失去可调整大小边框时也恢复全屏保护。拖拽、修饰键、安全桌面、3 像素触发区、32 像素重新触发区、左上角 500 毫秒等待均保持原规则。不增加轮询、线程或常驻进程。

状态新增 blockReasons（按键／拖拽、输入桌面、全屏等）、lastBlock（原因、PID、角落、时刻与窗口状态）及 maximizedClientEntries（原本会被全屏规则阻止、此次获准的角落进入次数）。仅存最末一次窗口元数据，不读取标题或窗口内容，不逐次写鼠标日志。现有 Status 请求才写状态文件。

## 验证

83 条核心回归覆盖窗口边界变化、已核验和未核验身份、全屏保留最大化标志但无边框、负坐标显示器、左右下角立即触发及空间重新触发。26 条配置／状态回归和 38 条原有底边规则／自有隐藏窗口属性回归通过；无生产鼠标或键盘输入提交。控制器编译通过。

全部实际游戏／浏览器全屏、多个显示器及睡眠恢复未逐一实测。如果未来客户端的真正全屏也同时保留原生最大化和 WS_THICKFRAME，本策略需重新核验，不能仅凭窗口名字扩大豁免。实际部署和用户验收结果记录在 verification-latest.json；组件 Ready 不代替用户动作成功。

参考公开契约：Microsoft IsZoomed 与 Window Styles 文档；源自本项目已有客户端底边适配的身份和几何规则，不声称新引入第三方 Mod 源码。

2026-10-13 部署后用户确认“两边都正常”，问题中包含 GPT 当前最大化及还原后重新最大化。只读状态记录左下 2 次、右下 2 次动作提交，拦截和失败均为零；开始菜单仍为 42 项紧凑排列，四组件 Ready。maximizedClientEntries=0，说明本轮没有观察到原本会被全屏规则拦截的那种边界；因此当前使用通过，原始偶发失败的唯一原因仍未完全证实。
