# 中间卡片维护说明

## 功能与布局

当前使用“应用｜单一卡片｜应用托盘”。时间、电池、媒体、CPU／内存和网速五页共用一个 104×44 DIP 的 Border，同一时刻仅一页可见，中间槽固定为 128 DIP；0.5.9 起比原来的 160 DIP 卡片缩窄 35%。向下滚轮依次前进，向上反向；支持细分滚轮余量，每个事件最多切一页，完整一轮回到原页。滚轮只在卡片真实区域内处理，页面切换不改变 Dock 宽度。没有自动轮播或媒体自动抢页，悬停不显示自定义文字提示。

0.8.5 起五页共用一层始终显示的圆角底色，沿用原悬停层的主题前景色和 0.12 不透明度；背景不随悬停、按下或换页改变。媒体按钮禁用时仍降低内容不透明度，键盘焦点及现有输入行为保留。

系统状态页使用两个直径 32 DIP、线宽 2.5 DIP 的矢量圆环，中心仅显示 CPU／内存名称，按占用率从顶端顺时针填充弧长，不在环内显示数字。精确数值保留在可访问性名称中。0% 只显示底环，未知值不伪造进度；100% 使用完整椭圆，避免弧段首尾重合导致消失。圆环复用几何对象，仍只按原有两秒可见采样更新，无动画或新计时器。

媒体标题和 72×24 DIP 的三按钮行各自居中。缺失的歌手信息不占布局列，有歌手时保留在可访问性名称中。媒体会话结束后显示“暂无播放”，按钮禁用，不擅自改选卡片。0.5.10 将空状态文字从 10 DIP 放大到 12 DIP，用户随后要求再大一级并把按钮稍微下移。0.5.11 的“暂无播放”为 14 DIP，文字行由 16 DIP 增到 20 DIP，上下外边距从 2 DIP 改为 0，按钮行因此下移 2 DIP；总高度仍为 44 DIP。活动媒体标题仍为 10 DIP，保留省略与完整的可访问性名称。电池图标与文字组成的横排按实际内容宽度居中，文字区仅设置 60 DIP 上限，不再固定占满 60 DIP；卡片及原生命中宽度保持 104 DIP。

0.5.12 根据用户要求移除卡片本体、CPU／内存和电池的全部自定义 ToolTip，不再在悬停时弹出标题、详细状态或“滚轮／左右键”说明。该修改直接删除提示内容的注册，刷新与换页也不会重新添加；不修改 Windows 全局提示设置。保留屏幕阅读器使用的可访问性名称，显示内容、布局和鼠标事件保持不变。

电池页与其他页互斥，不再额外占一块 52 DIP 卡片。沿用 0.5.1 的原生 ControlCenterButton 命中映射：保留原父对象、系统事件和可访问性对象，原始图形透明，卡片负责显示。仅选中电池页时映射完整 104×44 DIP 命中区；0.7.2 起切到其他页时同步撤去命中，但保持原生按钮已测量、透明且不能点击，避免下次切回时等待折叠对象重新布局。休眠按钮不参与 Tab 或可访问性控制视图，激活和停用时恢复原值／绑定；零宽布局槽不为旧位置留空。通过 XAML 命中检查后才禁用装饰按钮的鼠标接收，并把原生悬停状态传给它；映射失败保留 Invoke／Win+A 退路。卡片本体与命中适配共用宽度常量，防止下次调宽后留下旧范围。直接鼠标输入用于避免 Win+A 把快速设置切到键盘焦点模式；蓝色 Wi-Fi 开启状态保留。

原生按钮仍在托盘的原父对象下，滚轮在两者共享的 XAML 根上用 handledEventsToo 订阅，再按卡片实际边界过滤，因此电池页同样可以滚出，媒体按钮上滚动也不会漏掉事件。停止时撤销该订阅，不新增全局输入钩子或轮询。委托装箱与事件订阅参考 Microsoft UIElement.AddHandler 文档：https://learn.microsoft.com/zh-cn/uwp/api/windows.ui.xaml.uielement.addhandler 。

0.8.30 的消息队列监听、0.8.31 的默认滚轮转换均被真实手势否定。0.8.32 继续使用有模块校验的 InputSite 挂钩，但将卡片内触控板命中交给独立 DirectManipulation 视口，依据系统真实位移按主方向翻页。活动手势复用 XAML 帧事件，隐藏/结束即停止；无平移惯性。鼠标和 XAML 滚轮、原生电池及媒体点击保留。来源、生命周期和当前验收边界见 cards-input-latest.md。

用户确认双指与点击可用后，反馈单次滑动容易连续跨页。0.8.33 将触控板限定为一次接触序列最多一页：到达 48 DIP 后本次手势锁定，继续移动或反向不再翻页，抬手后重新滑动才重新计入。鼠标滚轮仍按原规则逐格切换，不增加固定时间冷却或新计时器。

用户随后确认 0.8.33 在松手时额外翻页。0.8.34 修正 READY 阶段的 ZoomToRect 坐标：使用内容原点及宽高，而不是卡片在输入窗口中的位置；同时在复位前关闭接触门闩，忽略没有活动接触的内容更新与 BEGIN 回调。取消、隐藏和尺寸变化也先关闭门闩再调用可能回调的 COM API。47 项测试通过，包含生产回调的迟到复位、短手势、取消和下一次接触；0.8.34 已由用户确认每次一页、松手不多切、下一次正常；后台 DMError=0、松手帧数稳定，临时观察已结束。

右键任一卡片和 Dock 空白打开 Win+X。0.7.7 以 ContextRequested 为主入口，保留经过最上层命中分类的 WM_CONTEXTMENU 作为消息路径；应用跳转列表、通知图标菜单和键盘上下文请求不改。0.5.4 使用当前 Taskbar.View.dll 的原生 ShowStartButtonContextMenuAsync 入口：只消费最近 1.5 秒内的一次真实 Dock 手势，把入口收到的 FrameworkElement 替换为相同 XamlRoot 内的原生参照控件。参照点位于点击横坐标、Dock 上方 8 DIP；它只有 1×1 DIP、透明、不能命中或通过 Tab 聚焦，不参与可见卡片宽度。坐标通过 XAML 变换换算，菜单的大小、布局、命中区域和子菜单继续由 Windows 同时计算。参照控件替换失败时保留原入口，不移动外层 HWND。

该入口的符号、四个 WinRT 值参数的间接传递及 AL 返回值已对照本机匹配的微软公共 PDB 和入口指令核验。仅替换第一个值，使用正常 COM 引用赋值；原函数仍消费全部参数并把它们移入原生协程。模块继续受既有 SHA-256、PE 时间戳和映像大小锁定。控件在停止时移除；一次性手势过期后不再影响原生键盘菜单，不增加计时器或进程。ABI 与符号证据见 menu-native-symbol-latest.json。

快捷键在真实 Dock 手势处理过程中，由 Explorer 激活自身窗口后发送。仅有 Win+A／Win+X／Win+N 三项固定动作；没有新增控制器消息接口、通用按键接口或提权操作。发送不完整时释放已提交的按键。命令提交成功不等于面板实际显示，必须保留真实点击验收。

## 布局所有权与退路

cards-latest.cpp 持有 RootGrid.Padding 和 BackgroundControl.Margin 的原始值，停止时恢复；这些属性不再由样式规则重复控制。覆盖布局为卡片分配零额外内容测量宽度，通过右内边距保留真实空间。共享 Dock 边界、玻璃和菜单定位使用扩展后的 TaskbarFrame。

空间不足时整体取消中间卡片占位，恢复紧凑原生电池入口。PowerReady 表示整个卡片槽已完成布局且能够容纳，PowerActive 表示当前选中电池页；两者分开，避免切到 CPU／媒体时又在托盘添一颗电池。四 DIP 滞回防止分数缩放边界抖动。页面变化通过已有 UI 线程内的托盘适配同步清理旧命中。0.7.2 以所有页面共用且已经布局的 LeanDockCard 槽为位置来源，不再依赖刚从 Collapsed 恢复的电池子页面尺寸；原生按钮及内部 Grid 实际尺寸一致后才能发布映射成功。初次布局仍由既有 LayoutUpdated 完成，不强制 UpdateLayout，不增加计时器或补点操作。

应用托盘保留原生父对象与点击对象，连续两排排布；奇数个应用时最后一颗整体上下居中，包括悬停和命中区域。托盘适配在 tray-cards-latest.inc 中，生成器将其插入受版本固定的上游适配。停止时按反序恢复依赖属性与绑定。多显示器与 DPI 切换还须实测，不能把单屏结果扩大。

## 数据与生命周期

CPU 使用 GetSystemTimes 两次差值，kernel 已含 idle。超过 64 逻辑处理器时不把部分组负载当整机。内存使用 GlobalMemoryStatusEx。现有 DispatcherTimer 仅在卡片可见且处于状态页时运行；隐藏或切换到媒体／电池后停止。0.5.10 在重现时保留上次已测圆环，可访问性名称标为“更新中（上次…）”；没有历史读数时保持空环并标“采样中”。重建基线后先用约 200ms 的真实区间更新，再恢复两秒周期；隐藏时段不混入这次占用率，没有后台常驻采样、伪造初值或新计时器。过早到达的旧 Tick 不能把不足 200ms 的区间发布为新值；无效／重置读数清空值，未知不是 0%。

媒体使用 SMTC 会话事件。回调排入 UI Dispatcher，弱引用和代次判断阻止过时结果覆盖新会话。按钮按会话能力启用，提交期间禁用。歌名只在内存，不写日志、不下载封面。

电池使用 GetSystemPowerStatus，并监听 PowerManager.RemainingChargePercentChanged、BatteryStatusChanged、PowerSupplyStatusChanged。回调合并后在 UI 线程刷新，Dock 从隐藏恢复、滚到电池页时也读取一次。卡片显示百分比及状态文字：正在充电时显示闪电与绿色电量条，已充满显示绿色，插电未充电与使用电池各有明确文字；断电低电量采用黄色，极低电量采用红色。阈值分别为 20% 与 10%，也尊重驱动提供的低电量／极低电量标志。未知电量不显示 0%，未知充电标志不当成正在充电，无电池不当作空电池。没有新增定时器或常驻进程。

停止时撤销所有媒体／电源订阅，取消挂起读取，停止计时器，移除新增 XAML、窗口属性并恢复布局。关闭中的状态禁止由 LayoutUpdated 重新建立卡片。

## 构建、诊断与回滚

0.7.2 已将快速设置改为与 Dock 同心；本机重复打开的 20 个可见采样中，中心偏差为 0 像素。保持电池目标已测量并不足以解决全部首次点击问题，用户仍报告“特别是回到桌面后 Dock 重新出现时”偶发需要补点，不得把这一轮记为点击验收通过。

0.7.3 为诊断候选，保留上述定位，新增仅电池页卡片范围内真实 PointerPressed／PointerReleased／Tapped 的只读计数。LeanDock.Card.Input.* 记录事件阶段、来源分类、是否已处理、相对原生命中偏移和原生控件状态；来源 1 为原生电池，2 为自定义电池按钮，3 为卡片容器，0 为其他对象。没有全局鼠标记录、轨迹、窗口标题、补点或新计时器，停止时移除订阅和属性。计数不会证明面板已显示，须与窗口的真实显示状态及用户报告对照。

2026-10-09 的失败样本：用户明确说“没弹出，已停住”；最后一条 Tap 来自原生按钮、Handled=0、原生偏移为零、Enabled/Hit 均为真。旧 ShellHost 进程在原控制程序持有的句柄上返回退出码 0，控制程序却已 Blocked，无法附加后续进程。这证明了宿主恢复缺陷，也排除了最后一条 Tap 完全落在按钮之外；尚不足以把全部漏点归因于进程更替。

0.7.4 在没有改变原生点击动作的前提下，将内部已加载 IconView 纳入输入就绪判断。缺失时保留已有自定义按钮的 Invoke／Win+A 退路，不能让一个有外框却无内部转发对象的容器独占输入。输入诊断增加 NativeIcons、NativeLoadedIcons、TapEnabled，供后续真实失败对照。快速设置只对已知零退出码恢复，60 秒内最多两次，异常退出与未知退出继续阻断。quick-lifecycle-latest.ps1 的 22 项检查包含真实测试子进程退出码、异常退出和重启预算；不操作生产 ShellHost，也不代替桌面点击验收。

0.5.8 新增的诊断中，View=0/1/2 分别是 CPU／内存、媒体、电池；VisiblePages 是当前可见页数，正常容纳时应为 1，空间不足时为 0。PowerActive 只在电池页为 1，Switches 为滚轮真正换页的次数，PowerUpdates 为电源读取次数；这些都不是额外的外部控制接口。0.5.9 修正首次绑定时尺寸属性被清除的问题，NativePowerWidth100／Height100 在成功映射后发布、解除映射时移除；真实点击仍需验收。

2026-10-08 的 0.5.8 用户实测回复：“切换、点击和电源状态变化都正常”。验收范围为单一卡片、三页双向滚轮（包括离开电池页）、电池左右键和实际插拔电源后状态变化。采样记录中 CPU 页与电池页边界均为 160×44 DIP，电池页停止 CPU 采样，离开电池页撤去原生命中。当前无活动媒体会话，媒体播放命令未在此轮重新验收；低电量、无电池和未知值通过逻辑检查，不能扩大为真实低电量硬件测试。

0.5.9 缩窄卡片并改为圆环后，用户实测确认：“比例和圆环合适，切换与点击正常”。该反馈覆盖紧凑比例、按弧长填充的圆环、滚轮切换和电池点击；此前 0.5.8 的电源状态变化验收继续保留，不扩大为本轮重新测试媒体播放或硬件边界。

0.5.10 用户确认 CPU 恢复刷新、空状态字号和电池整体居中“三处都正常”，随后继续要求调整空状态字号及媒体按钮位置。只读采样观察到首次 CPU 读数约 0.2 秒出现，之后约两秒更新、隐藏后停止；电池可见内容的中心偏差为水平 0.335 DIP、垂直 0 DIP，用户确认整体居中。0.5.11 沿用已验收的 CPU 与电池实现，新的媒体外观验收须单独记录，不能套用此前的反馈。

build/latest.ps1 重现生成源码。cards、surface 和 tray-cards 属于 Explorer DLL；0.5.5 沿用已验证的 Explorer DLL 和 Start companion，更新控制程序并加入快速设置位置组件，不改变触发角配置。维护生成适配时同时修改生成器或其引用的片段，不能只修改生成输出。

LeanDock.Card.* 提供只读数值：采样与错误计数、视图、媒体存在、电池值和卡片／控件几何。NativePowerHit 为原生命中检查结果，NativePowerClicks 只是收到的指针释放事件数，不等于面板显示成功。LeanDock.Shell.* 仅在固定按键动作后提供计数；LeanDock.Menu.NativeAnchor 表示原生参照控件已被入口接收，Error 表示设置时的异常。这些均不是外部命令通道，也不能单独证明菜单项可点击。真实布局还通过 latest-layout.json 记录应用数量、格子尺寸和坐标。

回归包含 cards-latest.ps1 的负载、电源未知值及空间边界，shell-actions-latest.ps1 的固定按键序列、参照点 DPI／负坐标／夹边与手势时限（不发送输入），geometry-latest.ps1 的共享坐标。源码构建和系统 DLL 依赖检查不能替代桌面点击验收。

2026-10-08 的第一版私有 COM 调用虽然返回成功，用户明确反馈“左右键直接没反应了”。该候选已撤回，恢复 0.5.0 后才重新读取实际菜单窗口。0.5.1 的事后移动仍会跳回旧位置；0.5.2 约束 HWND 位置后仍有初始闪跳，用户进一步发现菜单项无法点击。尚未部署的“更早约束 HWND”候选也随之放弃。0.5.3 撤去外层窗口定位，用户确认可以点开“设置”，成为此次回滚基线。0.5.4 改为原生 XAML 参照控件；最新实际验收单独记录，早先仅确认弹出位置的反馈不再视为完整点击验收。

更新 Explorer DLL 须备份、停止控制程序，干净重载经完整路径和会话核对的任务栏 Explorer；DLL 被映射时不覆盖。其他宿主同样按实际修改范围处理，0.5.5 首次加入快速设置组件无需重启 Explorer。回滚按哈希恢复既有代码、配置和二进制。绝不能按 latest.exe 文件名停止其他工具。

一次候选控制程序在 2026-10-08 被 Defender 行为监控拦截，相关任务也被移除，已用修改前的已验证程序及任务定义恢复。候选新增的管理员动作消息接口已撤回；正式实现不依赖它。没有关闭防护、添加排除或允许被隔离文件。完整运行和用户验收状态见 verification-latest.json。

## 快速设置首次定位（0.5.5）

用户指出连续左键电池时会先闪到屏幕右侧。此前控制程序收到 SHOW／UNCLOAKED 后启动 30ms 合并计时器，再调用 SetWindowPos，关闭时又恢复原位置；这些调用发生在面板已可见之后。0.5.5 移除快速设置的这条路径，开始菜单的原有路径保持不变。

小型 panels/latest.dll 通过一次性的目标 UI 线程 WH_CALLWNDPROC 接入，只对子类名 ControlCenterWindow、实际路径为系统 ShellHost.exe 的根窗口设置子类过程。控制程序预先核验 ShellHost.exe 与 ControlCenter.dll 的 SHA-256；组件内核对控制进程完整路径和会话。没有新增命令执行、按键或远程线程接口，不修改系统 DLL 文件。

WM_WINDOWPOSCHANGING 先交给原生窗口过程处理尺寸限制，再只改 WINDOWPOS 的坐标及必要的 SWP_NOMOVE；尺寸、显示隐藏、焦点和 Z 序保持原生。原生 WM_WINDOWPOSCHANGED 收到的是实际提交的位置。只靠 Dock 发布的标量边界计算，屏幕/DPI 边界无效时保留系统请求。面板隐藏时不撤销；Stop 或控制进程退出时撤销子类并有条件恢复最后原生位置。组件回调固定映射至宿主退出，防止悬空代码引用；没有位置轮询、补救移动循环或新增常驻进程。

同一 ShellHost 内重建窗口可以重新附加；早期版本对任意宿主退出都停止重试，0.7.4 改为上述带预算的零退出码恢复。新建宿主尚未被发现或没有有效 Dock 边界时，仍允许原生显示；冷启动首帧、多显示器/DPI 切换、媒体卡片动态高度和睡眠恢复须另行实测，不扩大重复点击测试的范围。

quick-position-latest.ps1 包含 57 项检查：分数缩放、负坐标、屏幕夹边、动态高度、show-without-move、只改变 Z 序、无效几何，以及测试自有隐藏窗口上的真实 Win32 消息周期和停用恢复。它不操作生产面板，不能单独证明面板视觉和点击正常。Status 新增 QuickSettingsPosition，Active/Adjustments 只表示接管与调整计数；验收仍以实际连续左键打开关闭及面板内点击为准。

## 0.7.7 右键菜单归属与事件路径

用户反馈第一次右键有时仍出现“任务管理器／任务栏设置”，第二次才出现 Win+X。本轮确认两个代码缺口：卡片原先监听 RightTapped，而本机 Taskbar.View 的公开符号包含 TaskbarFrame 的 ContextRequested 订阅；此外，旧处理函数只有在 Win+X 请求成功时才标记事件已处理，失败会继续传播。未抓到原生菜单刚弹出的现场，不能声称每次失败都由其中某一个条件造成。

现在在 TaskbarFrame 与 SystemTrayFrame 模板的子 Grid 上监听 ContextRequested，按 OriginalSource 的实际祖先链分清自定义卡片、普通背景、应用按钮和通知图标，在冒泡到父 Frame 之前消费自己拥有的请求。原生电池命中在实际 IconView 上使用同一个事件，停用及重建时撤销订阅；删除旧 RightTapped 动作入口，避免一份鼠标手势走两个不同动作入口。TryGetPosition 失败的键盘请求与已经处理的子控件请求保持原生。WM_CONTEXTMENU 退路改为只检查最上层可命中对象，不再把不可命中的后层对象当成点击目标。

归属判断和动作发送成功分开：属于卡片或背景的请求先标记已处理，再发送一次既有 Win+X；临时前台激活或输入失败不会放行另一份原生菜单。失败没有重试、补点或延迟计时器；只记录原因，以便区分“菜单漏出”和“命令没有打开”。快速设置与 Win+X 只有相同动作才适用原有 200ms 去重，不再互相吞请求。保留此前已验证的原生 XAML 参照点，不新增私有接口、符号、全局输入钩子或后台进程。

只读诊断：LeanDock.Menu.ContextSource 为 1=窗口消息、2=XAML 背景、3=XAML 卡片、4=原生电池；ContextCount、ContextSubmitted、ContextError 记录本地处理结果。LeanDock.Shell.LastResult 为 1=已提交、2=前台激活失败、3=输入未提交、4=相同动作合并；LastAction 使用 1=快速设置、2=Win+X。除 LastAction 沿用原始枚举值外，新数值属性保存值加一以区别缺失。停止时清理这些属性。计数和成功返回仍不代表菜单可见或能点击。

- https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.uielement.contextrequested

## 0.8.0 网速数据与生命周期

使用 Microsoft GetIfTable2 的 64 位 InOctets／OutOctets，通过 InterfaceLuid 匹配相邻读数。只汇总 HardwareInterface、OperStatusUp 的 Ethernet/Wi-Fi，排除 FilterInterface、EndPointInterface、未连接／暂停及虚拟接口，避免 Mihomo、Tailscale 等重复计量。它显示网卡收发总量（包含局域网），不探测外网、不记录网卡名称、IP 或访问内容。KB/MB/GB 为十进制字节每秒。

驱动查询放到短暂工作线程，UI 仅处理完成后的快照；同一卡片最多一个查询在途。复用原有 DispatcherTimer：只有网速页可见才运行；进入时先建基线，再用至少 200ms 的真实区间给出首个速度，稳态约一秒。切出或隐藏时清空基线和旧速度，迟到结果通过代次与停止标志丢弃。错误显示未知；断开显示零收发，新接口／计数回退／超过十秒的采样间隔重新建基线，不把累计计数当瞬时速率。GetIfTable2 分配的表通过 FreeMibTable 释放。DLL 沿用既有宿主寿命，不尝试运行时卸载。

新增数值诊断 NetworkActive、NetworkSamples、NetworkReceive、NetworkSend、PageCount、PreferencesValid；不提供远程选择或通用执行接口。逻辑与文件往返检查放在 cards-preferences-latest；真实点击、滚轮、单卡片布局、首次电池点击及返回桌面的背景刷新仍须单独验收，不能由单元测试替代。

## 0.8.18 网速汇总包含热点

用户选择始终显示网络链路收发总量。保留物理 Ethernet/Wi-Fi，并纳入 Type=IEEE80211、PhysicalMediumType=Native802_11 或 WirelessLan 的活动虚拟无线端口，覆盖本机 Microsoft Wi-Fi Direct 热点；不匹配本地化名称、接口编号或固定 IP。OperStatus、未连接／暂停、过滤层、端点及 TunnelType 仍作为排除条件。虚拟 Ethernet、TAP、WAN miniport、TUN、回环不计入；不假定所有 Virtual 接口都是无用重复，也不把所有接口无差别相加。其他驱动若不提供上述媒介属性，不能声称已覆盖。

转发流量在所选链路的收发两侧分别计入；例如上游接收 10 MB/s、热点发送 10 MB/s，就同时显示 ↓10 MB 与 ↑10 MB。这是明确选择的链路总吞吐口径，不是去重的互联网吞吐。数据仍取 GetIfTable2，没有抓包、代理配置改动、额外服务或新增常驻轮询。

复用 NetworkSampler 的 InterfaceLuid 匹配与重置保护：热点第一次出现或重新连接先建基线，避免新接口累计量混入；接口断开后从下一份快照移除；枚举顺序变化不改变身份。加入 NetworkInterfaces 数值诊断，仅记录当前参与采样的接口数量。辅助功能名称改为“网络总发送／总接收”；可见样式、右对齐、B/KB/MB 单位及滚轮行为不变。

回归覆盖真实网卡属性组合、物理网卡＋热点汇总、隧道中间层排除、热点断开／重连、大累计计数和枚举重排。真实热点数据与 Dock 读数仍需单独记录；模拟接口通过不能代替连接设备传输的验收。TrafficMonitor 的来源、版本和仅作实现参考的边界见 NOTICE.md。

`tests/network-observe-latest.ps1` 是手动运行的 5–60 秒只读对照工具：用系统网卡统计和 Dock 的数值诊断分别记录接口数、每秒速率及可见／隐藏状态，不激活窗口、不发送输入、不更改网络或制造流量。它记录实际采样窗口，不将采样时刻不同的数值强判为相等；未观察到可见网速页或活动热点时明确标记未观察到。2026-10-11 已在本机实际热点传输中观察到两个接口同时计入以及 MB 级 Dock 收发，具体样本和限制见 verification-latest.json。

## 0.8.5 卡片底色常显

用户不需要悬停时才出现选中底色，要求默认呈现同样质感，避免连续滚轮切页时背景变化。0.8.5 将原按钮上的 0.12 主题色悬停层移到五页共用的 Grid，使用 10 DIP 圆角、禁用该装饰层的命中；当时保留 #0CFFFFFF 基底。0.8.7 的主题配色替代了这两层颜色，固定显示与输入行为继续保留。

通用按钮模板和独立电池模板的 Normal、PointerOver、Pressed 共享同一外观；移除各自的 hover Border 与状态透明度 Setter。媒体按钮不再有单独的悬停色块，但保留 Disabled 内容透明度 0.30。电池原生输入适配可以继续发送原有状态名，它们现在不改变底色；不改命中、手势、诊断计数、原生菜单或回调的生命周期。共用背景不计入页面数，隐藏和停止仍由整个卡片容器负责。

## 0.8.6 电池提示与网速紧邻文字

用户截图显示的“电池状态：已充满 100%”属于原生 ControlCenterButton 范围内的 ToolTip，不是已移除的自定义提示。只在原生命中成功覆盖电池卡片后，检查该按钮及其子元素的 ToolTipService.ToolTip；已有 ToolTip 控件先关闭，再通过既有 DockRemember 保存原值／绑定并将附加属性设为 null。范围限制为该子树、最多 128 个节点／24 层，不修改系统全局提示和其他托盘。沿用已有布局更新及 PointerEntered 时机，处理重新生成的提示，不新增计时器、钩子或事件订阅。卡片空间不足回退到原生入口时恢复原值／绑定，停止时仍由原有属性回收流程恢复。

只读诊断 NativePowerTipOwners 记录保存过提示的所属元素数量，NativePowerTipsRemaining 记录已检查范围内未清除的数量，NativePowerTipScanComplete 标明是否检查完整，NativePowerTipError 为异常码；均使用既有数值加一约定。这些属性只证明处理情况，不代替停留悬停后的真实视觉验证。原生点击、右键和辅助功能名称保留。

网速按新明确要求取消数字列与单位列的独立占位，使用 CompactText 生成“500 B”“1.5 KB”这样的单个字符串，数值与单位之间始终仅一个空格。两行分别在固定 47 DIP 文字区域内右对齐，箭头和整组 60 DIP 宽度不变，单位前缀消失时数值自然靠向 B。长边界值仍通过 DownOnly 按需缩小，完整的每秒速率保留在辅助功能名称里。

## 0.8.7：玻璃与卡片的深浅色对比度

用户确认 0.8.6 的电池悬停提示和网速字距通过后，要求改善深色背景下的可读性。核查时系统与应用均为浅色，原材质只使用 0.10 tint 且提高饱和度，黑字背后透出深蓝壁纸；旧卡片还叠加同色黑色前景底层。

- 继续复用上游 WindhawkBlur 的现有合成实现及主题颜色解析；将 BlurAmount 从 8 调至 12、TintOpacity 从 0.10 调至 0.32、加入 TintLuminosityOpacity 0.35、TintSaturation 从 1.15 降至 0.85。主题色源仍是 SystemChromeAltHighColor，不增加截屏采样、常驻进程或定时器。
- 卡片使用本地 XAML ThemeDictionaries：Light 为 #7AFFFFFF，Default（深色）为 #70202732，HighContrast 使用系统窗口颜色。上传／内存与下载／CPU 分别使用随主题变化的绿／蓝，环轨道同步调整。前景沿用系统主题笔刷；日期、电源次要文字透明度提高至 0.82。
- 左右分隔线均使用系统前景色的渐隐渐变，整体 opacity 0.30。仍为 1×40 DIP，禁用命中；不改尺寸、页面顺序、鼠标事件、原生电池映射或网速排版。
- ThemeResource 交由 XAML 更新，无手写逐帧颜色逻辑。改动在独立的原生 XAML 表面内，不给应用图标染色。
- 编译、XML 结构、在线就绪与用户实际深浅色验收分开记录。高对比模式仅配置系统色回退，未切换用户桌面验证。
