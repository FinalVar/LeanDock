# 中间卡片维护说明

## 功能与布局

0.5.9 使用“应用｜单一卡片｜应用托盘”。CPU／内存、媒体、电池三页共用一个 104×44 DIP 的 Border，同一时刻仅一页可见，中间槽固定为 128 DIP；比 0.5.8 的 160 DIP 卡片缩窄 35%。向下滚轮依次前进，向上反向；支持细分滚轮余量，每个事件最多切一页，完整一轮回到原页。滚轮只在卡片真实区域内处理，页面切换不改变 Dock 宽度。

系统状态页使用两个直径 32 DIP、线宽 2.5 DIP 的矢量圆环，中心仅显示 CPU／内存名称，按占用率从顶端顺时针填充弧长，不在环内显示数字。精确数值进入悬停提示及可访问性名称。0% 只显示底环，未知值不伪造进度；100% 使用完整椭圆，避免弧段首尾重合导致消失。圆环复用几何对象，仍只按原有两秒可见采样更新，无动画或新计时器。

媒体标题和 72×24 DIP 的三按钮行各自居中。缺失的歌手信息不占布局列，有歌手时放入提示。媒体会话结束后显示“暂无播放”，按钮禁用，不擅自改选卡片。0.5.10 将“暂无播放”从 10 DIP 放大到 12 DIP；活动媒体标题仍为 10 DIP，保留省略和完整标题提示。电池图标与文字组成的横排按实际内容宽度居中，文字区仅设置 60 DIP 上限，不再固定占满 60 DIP；卡片及原生命中宽度保持 104 DIP。

电池页与另外两页互斥，不再额外占一块 52 DIP 卡片。沿用 0.5.1 的原生 ControlCenterButton 命中映射：保留原父对象、系统事件和可访问性对象，原始图形透明，卡片负责显示。仅选中电池页时映射完整 104×44 DIP 命中区，切到其他页时同步撤去命中并折叠原生电池按钮，避免盖住媒体控件；零宽布局槽不为旧位置留空。通过 XAML 命中检查后才禁用装饰按钮的鼠标接收，并把原生悬停状态传给它；映射失败保留 Invoke／Win+A 退路。卡片本体与命中适配共用宽度常量，防止下次调宽后留下旧范围。直接鼠标输入用于避免 Win+A 把快速设置切到键盘焦点模式；蓝色 Wi-Fi 开启状态保留。

原生按钮仍在托盘的原父对象下，滚轮在两者共享的 XAML 根上用 handledEventsToo 订阅，再按卡片实际边界过滤，因此电池页同样可以滚出，媒体按钮上滚动也不会漏掉事件。停止时撤销该订阅，不新增全局输入钩子或轮询。委托装箱与事件订阅参考 Microsoft UIElement.AddHandler 文档：https://learn.microsoft.com/zh-cn/uwp/api/windows.ui.xaml.uielement.addhandler 。

右键任一卡片打开 Win+X。Dock 空白的 WM_CONTEXTMENU 只在 XAML 命中确认无原生应用／托盘按钮时改为 Win+X。应用跳转列表和通知图标的菜单不改。0.5.4 使用当前 Taskbar.View.dll 的原生 ShowStartButtonContextMenuAsync 入口：只消费最近 1.5 秒内的一次真实 Dock 手势，把入口收到的 FrameworkElement 替换为相同 XamlRoot 内的原生参照控件。参照点位于点击横坐标、Dock 上方 8 DIP；它只有 1×1 DIP、透明、不能命中或通过 Tab 聚焦，不参与可见卡片宽度。坐标通过 XAML 变换换算，菜单的大小、布局、命中区域和子菜单继续由 Windows 同时计算。失败时保留原入口，不移动外层 HWND。

该入口的符号、四个 WinRT 值参数的间接传递及 AL 返回值已对照本机匹配的微软公共 PDB 和入口指令核验。仅替换第一个值，使用正常 COM 引用赋值；原函数仍消费全部参数并把它们移入原生协程。模块继续受既有 SHA-256、PE 时间戳和映像大小锁定。控件在停止时移除；一次性手势过期后不再影响原生键盘菜单，不增加计时器或进程。ABI 与符号证据见 menu-native-symbol-latest.json。

快捷键在真实 Dock 手势处理过程中，由 Explorer 激活自身窗口后发送。只有 Win+A／Win+X 两项固定动作；没有新增控制器消息接口、通用按键接口或提权操作。发送不完整时释放已提交的按键。命令提交成功不等于面板实际显示，必须保留真实点击验收。

## 布局所有权与退路

cards-latest.cpp 持有 RootGrid.Padding 和 BackgroundControl.Margin 的原始值，停止时恢复；这些属性不再由样式规则重复控制。覆盖布局为卡片分配零额外内容测量宽度，通过右内边距保留真实空间。共享 Dock 边界、玻璃和菜单定位使用扩展后的 TaskbarFrame。

空间不足时整体取消中间卡片占位，恢复紧凑原生电池入口。PowerReady 表示整个卡片槽已完成布局且能够容纳，PowerActive 表示当前选中电池页；两者分开，避免切到 CPU／媒体时又在托盘添一颗电池。四 DIP 滞回防止分数缩放边界抖动。页面变化通过已有 UI 线程内的托盘适配同步清理旧命中，随后原生 LayoutUpdated 完成新页的测量与映射。

应用托盘保留原生父对象与点击对象，连续两排排布；奇数个应用时最后一颗整体上下居中，包括悬停和命中区域。托盘适配在 tray-cards-latest.inc 中，生成器将其插入受版本固定的上游适配。停止时按反序恢复依赖属性与绑定。多显示器与 DPI 切换还须实测，不能把单屏结果扩大。

## 数据与生命周期

CPU 使用 GetSystemTimes 两次差值，kernel 已含 idle。超过 64 逻辑处理器时不把部分组负载当整机。内存使用 GlobalMemoryStatusEx。现有 DispatcherTimer 仅在卡片可见且处于状态页时运行；隐藏或切换到媒体／电池后停止。0.5.10 在重现时保留上次已测圆环，提示与可访问性名称标为“更新中（上次…）”；没有历史读数时保持空环并标“采样中”。重建基线后先用约 200ms 的真实区间更新，再恢复两秒周期；隐藏时段不混入这次占用率，没有后台常驻采样、伪造初值或新计时器。过早到达的旧 Tick 不能把不足 200ms 的区间发布为新值；无效／重置读数清空值，未知不是 0%。

媒体使用 SMTC 会话事件。回调排入 UI Dispatcher，弱引用和代次判断阻止过时结果覆盖新会话。按钮按会话能力启用，提交期间禁用。歌名只在内存，不写日志、不下载封面。

电池使用 GetSystemPowerStatus，并监听 PowerManager.RemainingChargePercentChanged、BatteryStatusChanged、PowerSupplyStatusChanged。回调合并后在 UI 线程刷新，Dock 从隐藏恢复、滚到电池页时也读取一次。卡片显示百分比及状态文字：正在充电时显示闪电与绿色电量条，已充满显示绿色，插电未充电与使用电池各有明确文字；断电低电量采用黄色，极低电量采用红色。阈值分别为 20% 与 10%，也尊重驱动提供的低电量／极低电量标志。未知电量不显示 0%，未知充电标志不当成正在充电，无电池不当作空电池。没有新增定时器或常驻进程。

停止时撤销所有媒体／电源订阅，取消挂起读取，停止计时器，移除新增 XAML、窗口属性并恢复布局。关闭中的状态禁止由 LayoutUpdated 重新建立卡片。

## 构建、诊断与回滚

0.5.8 新增的诊断中，View=0/1/2 分别是 CPU／内存、媒体、电池；VisiblePages 是当前可见页数，正常容纳时应为 1，空间不足时为 0。PowerActive 只在电池页为 1，Switches 为滚轮真正换页的次数，PowerUpdates 为电源读取次数；这些都不是额外的外部控制接口。0.5.9 修正首次绑定时尺寸属性被清除的问题，NativePowerWidth100／Height100 在成功映射后发布、解除映射时移除；真实点击仍需验收。

2026-10-08 的 0.5.8 用户实测回复：“切换、点击和电源状态变化都正常”。验收范围为单一卡片、三页双向滚轮（包括离开电池页）、电池左右键和实际插拔电源后状态变化。采样记录中 CPU 页与电池页边界均为 160×44 DIP，电池页停止 CPU 采样，离开电池页撤去原生命中。当前无活动媒体会话，媒体播放命令未在此轮重新验收；低电量、无电池和未知值通过逻辑检查，不能扩大为真实低电量硬件测试。

0.5.9 缩窄卡片并改为圆环后，用户实测确认：“比例和圆环合适，切换与点击正常”。该反馈覆盖紧凑比例、按弧长填充的圆环、滚轮切换和电池点击；此前 0.5.8 的电源状态变化验收继续保留，不扩大为本轮重新测试媒体播放或硬件边界。

build/latest.ps1 重现生成源码。cards、surface 和 tray-cards 属于 Explorer DLL；0.5.5 沿用已验证的 Explorer DLL 和 Start companion，更新控制程序并加入快速设置位置组件，不改变触发角配置。维护生成适配时同时修改生成器或其引用的片段，不能只修改生成输出。

LeanDock.Card.* 提供只读数值：采样与错误计数、视图、媒体存在、电池值和卡片／控件几何。NativePowerHit 为原生命中检查结果，NativePowerClicks 只是收到的指针释放事件数，不等于面板显示成功。LeanDock.Shell.* 仅在固定按键动作后提供计数；LeanDock.Menu.NativeAnchor 表示原生参照控件已被入口接收，Error 表示设置时的异常。这些均不是外部命令通道，也不能单独证明菜单项可点击。真实布局还通过 latest-layout.json 记录应用数量、格子尺寸和坐标。

回归包含 cards-latest.ps1 的负载、电源未知值及空间边界，shell-actions-latest.ps1 的固定按键序列、参照点 DPI／负坐标／夹边与手势时限（不发送输入），geometry-latest.ps1 的共享坐标。源码构建和系统 DLL 依赖检查不能替代桌面点击验收。

2026-10-08 的第一版私有 COM 调用虽然返回成功，用户明确反馈“左右键直接没反应了”。该候选已撤回，恢复 0.5.0 后才重新读取实际菜单窗口。0.5.1 的事后移动仍会跳回旧位置；0.5.2 约束 HWND 位置后仍有初始闪跳，用户进一步发现菜单项无法点击。尚未部署的“更早约束 HWND”候选也随之放弃。0.5.3 撤去外层窗口定位，用户确认可以点开“设置”，成为此次回滚基线。0.5.4 改为原生 XAML 参照控件；最新实际验收单独记录，早先仅确认弹出位置的反馈不再视为完整点击验收。

更新 Explorer DLL 须备份、停止控制程序，干净重载经完整路径和会话核对的任务栏 Explorer；DLL 被映射时不覆盖。其他宿主同样按实际修改范围处理，0.5.5 首次加入快速设置组件无需重启 Explorer。回滚按哈希恢复既有代码、配置和二进制。绝不能按 latest.exe 文件名停止其他工具。

一次候选控制程序在 2026-10-08 被 Defender 行为监控拦截，相关任务也被移除，已用修改前的已验证程序及任务定义恢复。候选新增的管理员动作消息接口已撤回；正式实现不依赖它。没有关闭防护、添加排除或允许被隔离文件。完整运行和用户验收状态见 verification-latest.json。

## 快速设置首次定位（0.5.5）

用户指出连续左键电池时会先闪到屏幕右侧。此前控制程序收到 SHOW／UNCLOAKED 后启动 30ms 合并计时器，再调用 SetWindowPos，关闭时又恢复原位置；这些调用发生在面板已可见之后。0.5.5 移除快速设置的这条路径，开始菜单的原有路径保持不变。

小型 panels/latest.dll 通过一次性的目标 UI 线程 WH_CALLWNDPROC 接入，只对子类名 ControlCenterWindow、实际路径为系统 ShellHost.exe 的根窗口设置子类过程。控制程序预先核验 ShellHost.exe 与 ControlCenter.dll 的 SHA-256；组件内核对控制进程完整路径和会话。没有新增命令执行、按键或远程线程接口，不修改系统 DLL 文件。

WM_WINDOWPOSCHANGING 先交给原生窗口过程处理尺寸限制，再只改 WINDOWPOS 的坐标及必要的 SWP_NOMOVE；尺寸、显示隐藏、焦点和 Z 序保持原生。原生 WM_WINDOWPOSCHANGED 收到的是实际提交的位置。只靠 Dock 发布的标量边界计算，屏幕/DPI 边界无效时保留系统请求。面板隐藏时不撤销；Stop 或控制进程退出时撤销子类并有条件恢复最后原生位置。组件回调固定映射至宿主退出，防止悬空代码引用；没有位置轮询、补救移动循环或新增常驻进程。

同一 ShellHost 内重建窗口可以重新附加；修改过的宿主进程一旦退出，本次控制进程不再附加其替代进程，避免反复崩溃。新建宿主尚未被发现或没有有效 Dock 边界时，仍允许原生显示；冷启动首帧、多显示器/DPI 切换、媒体卡片动态高度和睡眠恢复须另行实测，不扩大重复点击测试的范围。

quick-position-latest.ps1 包含 57 项检查：分数缩放、负坐标、屏幕夹边、动态高度、show-without-move、只改变 Z 序、无效几何，以及测试自有隐藏窗口上的真实 Win32 消息周期和停用恢复。它不操作生产面板，不能单独证明面板视觉和点击正常。Status 新增 QuickSettingsPosition，Active/Adjustments 只表示接管与调整计数；验收仍以实际连续左键打开关闭及面板内点击为准。

## 0.5.6 时序修补

开始菜单也改为宿主 UI 线程内的待提交位置调整，移除旧的 30ms 事后移动。两类面板共用定位计算，并读取同一版本的完整 Dock 边界。媒体命令在换会话时先废弃代次再取消，迟到结果不能影响新会话；卡片订阅和 UI 线程归属不变。智能隐藏的停止、重启、计时器及排队刷新也已补齐生命周期处理。详见 timing-latest.md，实际验收记录以 verification-latest.json 为准。
