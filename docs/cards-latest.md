# 中间卡片维护说明

## 范围与用户决定

用户在开始菜单布局完成后，选择 CPU／内存＋媒体控制。第一版固定为一个共享卡片，滚轮切换，保持原有应用和双排托盘。时钟、日期、输入法、网络／音量图标仍按既定配置隐藏。没有外部 API、天气、温度驱动或独立常驻进程。

## 布局所有权

`cards-latest.cpp` 在已验证的 Taskbar RootGrid 中创建自身的卡片和右分隔线。原来的左分隔线继续由 surface 管理。卡片宽 160、高 44、整个槽宽 184 DIP。

该组件单独持有 RootGrid.Padding 和 BackgroundControl.Margin 的原始值。这两个属性已从样式规则中移除，避免双重所有权、样式重施加和补位振荡。右内边距和背景负边距同时扩展；卡片使用零测量宽度的覆盖布局，保留真实的应用测量宽度，避免应用很少时被卡片的最小宽度撑开。原有背景比例计算、任务栏裁剪、共享 Dock 边界和菜单位置继续使用扩展后的真实 TaskbarFrame。

空间判定为应用测量宽度、托盘宽度、原边距、槽宽与外侧留白之和；四 DIP 的进入滞回避免分数缩放边界抖动。放不下时卡片、第二条分隔线和新增占位一起取消。

## 数据与生命周期

CPU 使用 GetSystemTimes 两次计数的差值；kernel 已含 idle，不能再次把 idle 加入分母。首个有效区间前显示“—”。内存使用 GlobalMemoryStatusEx。每个可见系统状态卡片有一个两秒 DispatcherTimer；隐藏或切换媒体停止，重新显示重建基线。

SMTC 管理器和当前会话均采用事件订阅。跨线程回调只排入 UI Dispatcher，异步读取使用弱引用和代次判断，旧会话的结果不会覆盖新会话。命令提交期间禁用按钮，按当前会话能力启用，API 返回失败不计成成功。停止时取消挂起读取、撤销事件、停止计时器、移除新增 XAML 并恢复两项原始属性；即使卸载引发布局事件也禁止重建卡片。

运行数据和标题只留在内存。`LeanDock.Card.*` 窗口属性提供只读诊断数字：实际采样次数、当前视图、媒体存在、API 失败计数和几何；没有可执行外部命令的窗口消息接口。

## 构建与回归

通过 build/latest.ps1 构建，生成器会重现 styler 接入，源文件仅加到已有 Explorer DLL。controller 和 Start companion 无需变更。cards-latest.ps1 覆盖 CPU 差值、布局和滚轮边界；geometry-latest.ps1 继续检查 Dock 坐标与菜单摆放。

更新时按主 README 的精确 Explorer 干净重载流程操作，不在已加载 DLL 上覆盖、不按文件名结束其他 latest.exe。生产备份包含上一版代码、构建收据、二进制、配置和计划任务定义。回滚脚本验证备份哈希，在任务栏宿主退出后恢复；新增且不再被旧构建引用的源文件可保留，不影响旧版本运行。

桌面视觉、真实滚轮、原生播放器控制、最大化隐藏后采样停止和恢复，以及原有托盘／开始菜单均需实测。单元测试和 API 测试不能扩大为这些场景的用户验收；最终状态见 verification-latest.json。
