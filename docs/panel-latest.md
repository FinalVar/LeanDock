# 详情面板改版（0.8.84，材质于 0.8.85、0.8.86 两次重做，0.8.88、0.8.89 加二级页）

用户 2026-10-31 要求：面板“看起来更高级”，包括主题风格、动效、液态玻璃，并消除“刚出现后几百毫秒才刷新出某些指标”。信息密度和命中区域沿用 0.8.83：宽 300 DIP，各控件坐标和 `PanelHit` 不变。

## 出数：悬停分两段

0.8.83 的面板在 0.4 秒悬停后才启动进程，CPU 要等 0.3 秒，网速和显卡要等 PDH 建查询（约 0.3 秒）再加一个采样间隔，亮度要等 WMI，弹出后约 0.6 秒才齐。

0.8.84：

1. 鼠标在时间键上停 `PrimeDelay` = 120 ms，后端以原有方式（哈希校验、普通令牌、挂起后发布 PID/Cookie 再恢复）启动面板进程。面板先启动采样线程，再初始化合成和 D2D，窗口保持隐藏。只是路过时间键（不足 120 ms）不启动任何东西。
2. 到 `RevealDelay` = 400 ms（与原悬停时长相同），后端先写 `LeanDock.Aggregate.Reveal` = 本次 Cookie，再给已发布的控制窗口发 `RevealMessage`。面板发布控制窗口后会检查这个属性，所以两边的先后顺序不会丢失显示请求；50 ms 计时器也会检查一次。
3. 显示时调用 `Metrics::Urgent()`：如果距上次采样已有 ≥100 ms，立即按待命期间的间隔计算 CPU、网速和显卡占用，不再等 0.3 秒的预热节拍。
4. 待命期间离开时间键：面板自己的 250 ms 离开判定结束进程；点击时间键、任务栏隐藏等原有路径仍由后端 `ClosePanel` 清掉属性。待命 4 秒仍未显示则自行退出。
5. 上一个面板正在收起时重新悬停：后端看到它已撤回控制窗口，就每 50 ms 等它退出，再启动并立即显示新面板。

隐藏时不采样的约束不变：面板进程只在鼠标停在键上或面板打开时存在。

### 显卡占用改用 D3DKMT

PDH 的“GPU Engine”计数器和任务管理器读的是同一组内核节点计数。改为直接调用 gdi32 导出的公开 D3DKMT 接口（SDK `shared/d3dkmthk.h`）：

- `D3DKMTEnumAdapters2` 得到适配器句柄；`KMTQAITYPE_ADAPTERTYPE` 取适配器类型；`KMTQAITYPE_NODEMETADATA` 取每个节点的引擎类型；`D3DKMTQueryStatistics(NODE)` 取节点累计运行时间（100 ns）。
- 只算 DXGI 枚举到的非软件、非远程适配器，且类型字带 RenderSupported、不带 SoftwareDevice。参考机上 AMD 核显有一个间接显示别名（类型 0x342，无渲染位），它的节点计数与核显完全相同；PDH 不列它，新规则同样排除。
- 每个适配器的 3D 占用取其最忙的 3D 节点（不跨节点相加），与原来“同一引擎跨进程求和、引擎间取最大”的定义相同。
- MinGW 没有 d3dkmthk.h，`aggregate/gpu-latest.h` 只声明用到的字段，并用 `static_assert` 锁定 SDK 10.0.26100 的布局（节点元数据在 SDK 中处于 `pack(1)`，大小 78）。
- 2026-10-31 参考机核对：空闲 2 秒内 D3DKMT 与 PDH 对同一引擎给出相同数值（AMD 3D 0.50%、Copy 0.13%）；面板探针列出的显卡与 0.8.83 相同（D58B、E20E）。

面板不再链接 pdh。

## 材质：液态玻璃的近似（0.8.85 重做）

### 0.8.84 为什么失败

用户实机看到的是一块近乎不透明的浅色板（“根本没有液态玻璃效果，云母都算不上”）。原因有二，都是 0.8.84 的离屏检查看不出来的：

1. DWM 交给 `CreateHostBackdropBrush` 的背景**已经是重度模糊过的**。2026-10-31 在实机上把玻璃层的模糊、调色、色调全关掉截图（`glass-check --raw`），背后测试窗口里 22 px 的文字完全看不出来。0.8.84 再叠一层 30 的模糊、0.5 倍亮度压缩和 62% 白色，背景只剩约 19% 的明暗变化，背后是白色窗口时就是一块白板。
2. 离屏检查用的 `CreateBackdropBrush` 采的是同一棵合成树里的测试壁纸，没有这层预模糊，所以图上看起来通透。

还试过“折射”：用 D2D 2D 仿射变换把背景在边缘放大。合成器只接受把变换直接作为整个效果图的根，且一旦它的输入是背景画刷，`SetSourceParameter` 就返回 E_INVALIDARG（同样测于实机）。背景画刷不能被变形，真折射只能实时截屏再处理，不做。

### 0.8.85 为什么也失败

0.8.85 为了“通透”做了三件事：玻璃层只铺 88%，让 DWM 透出背后清晰的桌面；每段文字挂一层白色柔光；边缘加一圈 13 DIP、饱和 2.6 的艳色磨砂带。用户实机的评价是“闪花眼，都没有原来的好”。从用户发来的截图看：清晰的壁纸纹路叠在模糊背景上成了重影，文字边缘被柔光晕开发虚，边缘色带比中间更艳更跳。三样都在制造视觉噪声，不是玻璃感。

### 现在的做法（0.8.86）

只保留柔和的磨砂底和真正服务于“玻璃厚度”的细线条：

| 层 | 内容（`Scene::Look`，浅色 / 深色） |
|:--|:--|
| 阴影 | 软阴影 22/9 + 1.5 的紧贴阴影，透明度 0.22/0.14 · 0.55/0.45 |
| 玻璃 | HostBackdrop（已模糊）→ 饱和 1.3 → 伽马曲线 `out = a·c^e + o`：浅色 0.45·c^0.6+0.55，深色 0.45·c^1.5；铺满 |
| 色调 | 浅色白 8%，深色 #101216 25% |
| 边缘厚度 | 约 7 DIP 的渐隐色带：浅色黑 10%，深色白 6%；背后是白色窗口时也能看出玻璃的厚度 |
| 高光 | 跟随指针的柔光（半径 170）和只在边圈里的亮点（半径 120） |
| 受光边 | 1 DIP 外描边：左上最亮、右下次亮、两侧暗；内侧顶部 1 DIP 内光；最外 0.75 DIP 发丝线（浅色黑 9%，深色黑 27%） |

和 0.8.84 比：0.8.84 在已模糊的背景上再模糊 30、线性压缩到一半亮度再盖 62% 白，背景几乎只剩一层白；0.8.86 不再加模糊和厚白，背后的颜色和明暗能看出来，但没有清晰重影。

伽马曲线代替原来的线性压缩：浅色把暗处提得多、亮处几乎不动，背后是纯黑时玻璃约为 sRGB 0.53（主文字约 4.8:1），背后是中灰时约 0.82，纯白仍是白；深色反过来，背后纯白时约 0.39。这样暗背景下仍可读，亮背景下颜色和明暗变化都保留。代价：背后是大块深色时，浅色面板上次要文字的对比度会明显下降（测试背景右下的深蓝区）。

`GammaTransferEffect` 写在 `aggregate/glass-latest.h`，沿用 `effects-latest.h` 的接口写法，但不改那份上游提取的文件。离屏检查给普通背景画刷补一个 28 的模糊来模拟 DWM 的预模糊（`Scene::HostBlur`），让 `material-*.png` 和实机接近。

真实桌面检查：`tests/aggregate-glass-latest.ps1` 编译一个测试程序，把生产用的 `Scene` 和面板内容在屏幕下方中间显示约 1 秒并截下该区域；`--backdrop` 先铺一块满是文字和色块的测试窗口，`--raw` 只显示未经处理的背景，`--set 字段=值` 覆盖 `Scene::Look`。它会出现在屏幕上，所以不进自动测试。2026-10-31 用它比较过：用户的蓝色壁纸、浏览器白底、终端黑底和测试背景，浅色与深色。

系统“透明效果”关闭时隐藏玻璃层，色调改为不透明。

控件：开关在开启时用系统强调色渐变填充，字色按亮度在黑白之间选；关闭时是带 1 DIP 顶部受光边的浅玻璃片。滑块是 Windows 11 式白色圆钮加强调色内点，悬停或拖动时内点放大。CPU 趋势改为渐变面积加圆头折线和末端光点。分隔线两端渐隐。时间的时、分用 Segoe UI Variable Display 28 px，秒用 16 px 次要色，基线对齐。

强调色取 `UISettings`：浅色模式 AccentDark1，深色模式 AccentLight2，与 Windows 11 快速设置一致；读取失败时回到原来的青绿色。主题或强调色变更沿用已有的 `WM_SETTINGCHANGE` 刷新。

## 动效

- 入场：玻璃从时间键上方（中心点在面板右下、距右缘 36 DIP）放大 0.94→1、上移 12 DIP、淡入，曲线带约 1% 回弹。内容是同一张绘制表面，按 `PanelLayout::Cuts()`（只在区块和行的空隙处切）分成 6 条带，从上到下每条延后 28 ms，各自上移 10 DIP 并淡入。
- 收起：用户造成的收起（离开、Esc、点击外部、打开设置页）在 150 ms 内淡出、缩到 0.97 并下沉；开始收起时立即恢复点击穿透，并先撤回控制窗口属性。锁屏、睡眠、属主失效、`WM_CLOSE` 仍立即结束。
- 交互过渡：悬停底色 120 ms，开关填充 180 ms，非拖动引起的滑块变化（键盘调音量、首次读到亮度）240 ms。拖动时滑块直接跟手，不做缓动。只有过渡进行时才开 16 ms 的重绘计时器，结束即停。
- 系统关闭“动画效果”（`SPI_GETCLIENTAREAANIMATION`）时，入场、收起和交互过渡都直接到终态。

绘制表面改为原地重绘（`Drawing::Redraw`），不再每秒新建表面和视觉对象。

## 亮度调节误报失败（0.8.85 修复）

拖亮度条时面板显示“亮度调整失败，设备可能已断开”，但亮度其实已经改了。`WmiSetBrightness` 在 WMI 里声明为无返回值的方法，调用成功时 `GetResultObject` 返回 S_OK 和空对象（实机核对：同值设置，`exec 0`、`result 0 object=null`）；原代码把空对象当成失败。现在只有明确的非零返回值才算失败，之后照旧读回实际亮度。这段代码来自胶囊版，不是 0.8.84 引入的。

## Wi-Fi 箭头只打开快速设置首页（0.8.87 修复）

用户在 Windows 26H2（build 26300）上点 Wi-Fi 开关右边的箭头，出来的是快速设置首页，不是网络列表。这一版的快速设置由 `ShellHost.exe` 承载，注册了 `ms-controlcenter:` 协议；`ms-availablenetworks:` 仍能用，但只到首页。系统自己的投屏面板用 `ms-controlcenter:wifi`，2026-10-31 在实机上用它直接打开了 WLAN 列表页。现在注册了 `ms-controlcenter` 的系统用新链接，没注册的照旧用 `ms-availablenetworks:`。新链接打开的列表出现在屏幕下方中间，不贴着托盘，这由系统决定。

## 二级页与 Wi-Fi 页（0.8.88）

用户看 0.8.87 后指出问题不在“进不进得了列表”，而在“这整套面板只做了一级界面，到二级就变成系统默认的样式”。定下的要求：Wi-Fi 列表、蓝牙设备、移动热点、音量细节都做成面板自己的二级页；整页滑入，宽度不变，左上角返回；面板里永远不跳系统界面，做不了的入口直接去掉。0.8.88 先做页面框架和 Wi-Fi 页，其余三页随后。

**入口**：Wi-Fi 磁贴右侧箭头进入 Wi-Fi 页。蓝牙、热点、深色主题的箭头去掉，整块 132 宽都是开关；蓝牙、热点的页做好后再加回箭头。`ms-controlcenter:wifi` 等系统链接不再使用。

**框架**：`Scene` 里主页的各个区块放进 `mainLayer`，二级页是同一层玻璃上的另一张绘制表面 `pageLayer`。进入时主页左移 36 并淡出、二级页从右侧 36 处滑入（220/300 ms，延迟 40 ms，与入场同一条 Settle 曲线），返回反过来；每次都从当前值开始，来回快点不会跳。系统关闭动画效果时直接切换。二级页沿用主页的高度，返回时面板不改变大小。面板每次悬停都是新进程，所以每次打开都从主页开始。

**数据**：`WifiBackend` 只在 Wi-Fi 页开着时存在于 Metrics 工作线程里，离开页面或面板收起就取消全部异步操作、关 WLAN 句柄、清空列表。

- 行来自 WLAN 服务缓存的 `WlanGetAvailableNetworkList`：页面一打开就有，带“已保存”“已连接”标记，同名的“有配置文件”和“无配置文件”两条合成一行；信号质量 0–100 按 25/50/75 分成 1–4 格。隐藏网络（无名称）不显示。
- WinRT `WiFiAdapter::ScanAsync` 只用来刷新这份缓存：打开时扫一次，之后每次扫完隔 15 秒再扫。实机上一次扫描要 5–10 秒（10.1 s、5.2 s、5.8 s），最初按 10 秒超时取消，结果总是拿不到新列表；现在上限 30 秒。
- 连接用 WinRT `ConnectAsync`（带 `PasswordCredential` 时由系统建配置文件，个人与企业网络都适用）。它需要 WinRT 自己报告里的网络对象；网络还没出现在报告里时，等这一轮扫描结束再连，期间显示“正在连接…”，扫完仍没有就报“网络不在范围内”。连接 40 秒没结果算超时。
- 页开着时行的顺序固定：首次按“已连接→信号→名称”排序，之后已有的行保持原位，新出现的排在后面，只有连上的网络会移到最上面。这样正在输入密码的那一行不会跳走。

**输入**：面板窗口平时不抢焦点（`WS_EX_NOACTIVATE`）。点密码框时面板用 `SetForegroundWindow`+`SetFocus` 取得键盘焦点（这次点击本来就是给它的输入），并解除输入法关联，密码不经过输入法。支持字符输入、退格、回车连接、Tab 在用户名与密码间切换、Ctrl+V 粘贴；不能移动光标或选中文字。密码上限 63 个字符。焦点被别的窗口拿走就退出输入状态。输入时鼠标移出面板不再 0.25 秒后收起；Esc 第一下只退出输入框，松开后再按才关闭面板。

**密码**：只存在于 Wi-Fi 页的视图状态和发给工作线程的那一条命令里。展开另一行、收起、返回主页、面板关闭和发送连接后都用 `SecureZeroMemory` 擦除；进入 WinRT 凭据对象后原字符串立即擦除；排队中的命令在停止时擦除。不写日志、不写文件。

**界面**：页头是返回箭头、15px 半粗标题和右侧 Wi-Fi 开关（与磁贴同一状态和过渡）。每行 48 高：自绘信号弧（点加三段弧，按格数点亮）、加密网络加小锁、名称、副标题（已连接/已保存/安全/开放/企业网络/正在连接…）。展开的行用磁贴同样的控件底色和受光边，内含状态或错误行、输入框、按钮（“连接”用主题色渐变，“断开连接”用次要样式）。列表区可滚轮滚动，展开时自动滚到整行可见。空状态只有一行字：Wi-Fi 已关闭、硬件开关关闭、正在查找网络、附近没有网络或拿不到权限的原因。

**检查**：`--hidden-probe` 增加 Wi-Fi 模型断言（排序、布局、命中、表单是否可提交、重输密码、滚动到可见、擦除）和离屏渲染 `control-panel-probe/wifi-dpi-100/200.png`（浅色正在输密码、深色企业网络报错）；`tests/aggregate-glass-latest.ps1` 加 `--wifi`，在真实桌面上截 Wi-Fi 页的玻璃。2026-10-31 另用一次性程序在实机上跑了真实的 Metrics 工作线程 16 秒（只读）：缓存列表首次读取即有，扫描 10.1 s 完成，附近只有 NWAFU 一个名字（13 个接入点）合成一行，已保存、已连接；切回主页后列表清空。

## 蓝牙、热点、声音页（0.8.89）

用户实机确认 Wi-Fi 页能输入密码后，其余三页按同一套框架补齐。

**入口**：蓝牙、移动热点磁贴加回右侧箭头（与 Wi-Fi 磁贴同样 100/32 分割）。音量行右侧加一个箭头进入声音页；为它让位，两条滑块的右端从 244 移到 218、数值从 252–286 移到 222–254，亮度行同样对齐，右侧留空。命中区相应收窄（滑块 52–224，箭头 256–288）。滑块的绘制抽成 `PaintSlider`，主页与声音页共用。

**共用部分**：`PageList`（列表区顶端、底端、滚动范围、`Reveal` 和 `Inside`）、`PaintScrollbar`、`PaintPageFooter` 从 Wi-Fi 页抽出。任一页上出现控件错误（例如无线授权、切换输出失败）时，列表底部让出一行显示，5 秒后消失。命令统一由 `Metrics::Send` 发出，`ControlCommand` 的 `ssid` 字段改名为 `key`，可以是网络名、设备 ID、端点 ID 或应用键；带秘密的命令（Wi-Fi 密码、热点密钥）走同一个 `Secret` 路径，入队前擦除调用方的副本。各页的后台只在该页打开时存在于 Metrics 工作线程里，离开页面或面板收起即关闭并清空数据。

**蓝牙页**（`bluetooth-latest.h`、`bluetooth-page-latest.h`）：

- 列表来自已配对的关联端点：`DeviceInformation::FindAllAsync`，AQS 为 `System.Devices.Aep.IsPaired` 且协议为经典蓝牙或 BLE，附带 IsConnected、ContainerId、经典设备的 Class of Device 主次类、BLE 的 Appearance 类别。这是 Windows 已保存的记录，不发起扫描。页开着时每 2 秒重读一次，排序规则与 Wi-Fi 页相同（首次按“已连接→名称”，之后保持原位）。
- 图标：经典设备按 CoD（主类 4 的耳机/免提/头戴为耳机，其余为音箱；主类 5 的键盘、指点位为键盘、鼠标，低 4 位 1/2 为手柄），BLE 按 Appearance（0x00F 的子类 1/2/3/4，0x001 手机，0x002 电脑，0x021 音箱）。有蓝牙音频端点时按端点的形态改为耳机或音箱。
- 电量：对已连接的设备，按其容器 ID 查询设备节点的 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2`（设置页显示的同一项），每台每 30 秒最多一次，同一时刻只有一个查询。驱动不提供就不显示。用“不为空”的 AQS 一次查全部，实机返回 E_INVALIDARG，所以按容器逐台查。
- 连接/断开：只对有蓝牙音频端点的设备开放（行可以展开）。找出容器 ID 相同的渲染/采集端点，经 `IDeviceTopology` 找到它们背后的 KS 滤波器，对每个滤波器（A2DP、免提各一个）发 `KSPROPSETID_BtAudio` 的一次性属性（0 重连、1 断开，GET）。这是 ToothTray 的做法，系统设置里的“连接”按钮背后也是这类请求。之后每 0.5 秒重读，状态变到目标即完成；20 秒未变报错。鼠标、键盘等由 Windows 在设备唤醒时自己重连，页面上只显示状态、行不能展开。
- 不做：配对新设备（PIN、确认数字等多种配对仪式）、删除设备。空列表时提示“新设备请在 Windows 设置中配对”，不放链接。

**热点页**（`hotspot-page-latest.h`，读写在 `ControlBackend` 里，与磁贴共用同一个 `NetworkOperatorTetheringManager`）：

- 显示网络名称、密码、频段、共享来源（当前 Internet 连接配置文件名，用户机上是 mihomo）、已连接设备（`GetTetheringClients`：主机名去掉域后缀，IPv4 地址，没有就显示 MAC）和“已连数 / 上限”。读取 `GetCurrentAccessPointConfiguration` 实测 0 ms，所以页开着时随详情节拍每秒读一次。
- 密码默认是圆点。密钥不进 `Sample`（`Sample` 每次绘制都会复制）：工作线程把它写进 `Metrics::hotspotKey`（预留 64 字符、受锁保护），离开热点页或面板关闭时擦除；只有点眼睛或开始编辑时，界面才把它复制进视图里预留好的缓冲区，收起或离开即擦除。
- 编辑：只在热点关闭时可用（运行中改配置的系统行为未验证，不拿用户正在用的热点试），开着时按钮置灰并提示“关闭热点后可以修改”。表单是名称、密码（预填当前值）、频段三选一（不支持的频段置灰）。校验按 Windows 的限制：名称 1–32 字节 UTF-8，密码 8–63 个可打印 ASCII 字符。保存走 `ConfigureAccessPointAsync`，15 秒超时；成功后立即重读并回到详情，失败留在表单显示原因，密码框回填旧密钥。
- 输入同样经 `TakeKeyboard` 取前台和焦点。密码框关闭输入法；名称框可能要输中文，改用默认输入法，组字窗放在输入框正下方。Tab 在两框间切换时同时切换输入法。退格会先把被删的字符清零再弹出，Wi-Fi 页一并改用这种写法，这样擦除缓冲区时不会在长度之外留下删掉的字符。
- 排队的带密码命令（Wi-Fi 密码、热点密钥）：命令里的密码字符串先预留 64 字符的堆空间再拷入，之后经队列的每次移动只转交指针。0.8.88 起是直接拷贝，10 个字符以内的密码会放在字符串对象内部，移动后旧位置可能留下副本；这次一并改掉。

**声音页**（`sound-latest.h`、`sound-page-latest.h`）：

- 顶部是总音量（与主页同一控制和请求显示），下面“输出设备”和“应用”两段可滚动。
- 输出设备：所有活动的渲染端点，两行显示（设备描述“扬声器”+接口名“Realtek(R) Audio”），图标按端点形态。点非当前的一行即切换：通过 PolicyConfig 客户端的 `SetDefaultEndpoint` 把它设为控制台、多媒体、通信三个角色的默认设备，与 Windows 设置的效果相同。这个接口没有公开文档，按 EarTrumpet、AudioDeviceCmdlets 长期使用的布局声明（只参考，不复制代码）。
- 应用：默认输出上所有未过期的会话，同一程序（按可执行文件路径）合成一行，“系统声音”排第一，其余按名称且之后保持原位。名称依次取会话显示名（`@` 资源串经 `SHLoadIndirectString`）、程序文件说明（版本信息 FileDescription，新链接 version 库）、文件名。图标在界面线程用 `SHDefExtractIconW` 按面板 DPI 取 20 DIP，每个面板进程只取一次。滑块拖动与主页一样每 75 ms 最多发一次、松手发最终值，同一程序的所有会话一起设置；拖动非零值时自动取消静音。点图标切换静音，静音时图标变淡、加小静音标、滑块变灰。
- 页开着时每秒重读一次（同步 COM，无异步、无回调）。

**检查**：`--hidden-probe` 新增 `VerifyPageModels`（CoD/Appearance 分类、副标题、展开与命中、页脚让位；热点的名称和密码限制、各控件命中、擦除、可编辑条件、频段名；声音页的行结构、主音量与应用命中、拖动节流），`policyChecks` 共 222 项；离屏渲染 `bluetooth-`、`hotspot-`、`sound-dpi-100/200.png`；真实采样阶段依次打开三页（只读），记录蓝牙页是否读到、设备数，声音页输出数和应用数，热点页是否读到名称和密钥（只记是否读到），以及回到主页后页面数据是否清空，写进 `controls-probe-latest.json`。玻璃检查的 `--wifi` 扩展为 `--page wifi|bluetooth|hotspot|sound`。

2026-10-31 用户机上的只读结果：蓝牙关着、没有已配对设备（查询 31 ms 返回 0 条）；一个活动输出（Realtek 扬声器）和一个未插的耳机口，会话只有系统声音；热点开着，名称 xcan，5 GHz，支持任何/2.4/5 GHz，无客户端；回主页后数据清空。

**未验证**：真实蓝牙耳机的连接/断开和电量（用户机上没有已配对设备）；保存热点设置（不在用户正在用的热点上试）；切换输出设备（只有一个输出）；带图标的应用行；三页在真实桌面上的玻璃观感（测试时电脑锁屏，截到的是锁屏画面）。

## 验证与边界

- `--hidden-probe` 新增：D3DKMT 适配器类型、节点占用计算、过渡状态机的断言；把真实的浮动 `Scene` 放到一张测试壁纸上，用 `BackdropBrush` 代替只在真实窗口后面才有的 HostBackdrop，通过 Windows.Graphics.Capture 读出浅/深色静态图和入场、收起的逐帧图（`control-panel-probe/material-*.png`）。脱离窗口的捕获树不会推进合成动画，所以逐帧图由 `RevealFrame`/`LeaveFrame` 按与真实动画同一张时序表（`Scene::Timing`）摆出各时刻的静态值；它验证时序和观感，不验证合成器实际播放。不显示窗口、不截屏、不发送输入。截图失败只记日志，不判定探针失败。
- 生命周期夹具（编译真实 Panel，只用隐藏窗口）新增待命显示门控：没有本 Cookie 的显示属性时不显示，Cookie 被替换后旧的显示属性失效，待命中退出不等收起动画。真实子进程只接受 Explorer 的 Shell_TrayWnd 作为属主，夹具不放宽这项检查，所以属主与子进程之间的完整握手只能由真实悬停验证。
- 未自动验证：真实桌面上的 HostBackdrop 观感、120 ms 预启动在实际鼠标移动下的手感、真实悬停时出数是否已齐、收起动画与重新悬停的衔接。以上需要用户实机确认，记录在 verification-latest.json。
- Wi-Fi 页未自动验证：真实悬停下的滑入手感、点击输入框能否拿到键盘焦点（取决于系统前台锁，需实机确认）、真实连接带密码网络和企业网络、滚轮在面板上的表现。实机只有一个开放网络，带密码的连接路径只有模型和离屏检查覆盖。
- 预启动意味着鼠标在时间键上停够 120 ms 但不足 400 ms 时，会启动一次面板进程并在离开后约 250 ms 退出；这比原来多一次短暂的进程启动，换取弹出即有数。
