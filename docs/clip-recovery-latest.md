## 实际证据与原因

- 原窗口裁剪框为 (972,-7)-(1588,89)，宽 616、高 96；负的 top 并非单纯的隐藏
  动画中间态。Dock 完全展开时，75 秒记录中仍保留这个范围。
- Dock 内容随后扩展至 (912,0)-(1648,96)，宽 736，但窗口仍沿用旧裁剪框。
  用户截图中的两侧矩形截断与此一致。
- 保留的上游 Styler 会比较当前窗口区域与上次由自己设置的区域；只要框不相同，
  且并非全窗区域，就视为另一个所有者设置的范围，主动让出控制。这是保护系统
  平板任务栏折叠行为所需的边界，但它把这个整体上移、尺寸未变的旧范围也排除了。
- 让原有已加载的 Styler 重新生成区域后，得到 (933,0)-(1627,96)，与当时内容
  宽度 694 一致。后续内容变宽、变窄和自动隐藏时均继续更新。

已解释的是旧范围为何一直不更新。最初哪个系统调用使区域整体上移 7 像素，
本次未追踪到；不能把这个初始变化归因于某个具体程序或先前一次 Z-order 操作。

## 最小源码适配

继续复用 upstream/styler.cpp 原本的区域生成、窗口消息、布局回调、缓存和清理。
生成器只放宽一种明确匹配上次自有区域的状态：当前区域为简单矩形、左右边界
完全相同、上一范围覆盖窗口全高、当前高度也不变，仅向上平移且仍与窗口相交。

这种状态允许按当前 XAML 布局重新生成，但不能命中“不变则跳过”的缓存条件。
停止时也使用同一判定，避免留下这份自有但已平移的区域。

实际缩短的折叠区域、不同宽度、复杂区域、空区域、未知所有者、窗口高度或 DPI
已变化的旧区域继续遵循上游保护，不强制展开或覆盖。没有新增轮询、常驻程序、
外部窗口搬移或专用 Hook。
