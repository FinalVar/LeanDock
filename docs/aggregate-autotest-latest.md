# 聚合面板自主验证流程

## 使用范围

用于聚合时间键、悬停面板或相关故障的维护。用户希望助手自行测试、定位、修复并复测，减少反复要求用户操作和报告。流程由当前任务执行，不安装服务、计划任务或永久观察器；一轮有界检查结束即退出。后续改动或新异常才重跑相关项。

入口：`tests/aggregate-autotest-latest.ps1`。需要本机已有的LeanDockToolchain与PowerShell 7。测试使用隐藏自有窗口、正式面板的精确二进制副本、只读设备接口和生产绘制器离屏输出，不发送桌面输入、不截图、不切换前台、不触发正式Dock的Update/Stop/Start。

## 一轮检查

```powershell
& 'C:\Program Files\PowerShell\7\pwsh.exe' -NoProfile -File .\tests\aggregate-autotest-latest.ps1 -ProbeCycles 3 -ObserveSeconds 30
```

1. 保存正式运行文件和配置哈希、Explorer PID与组件状态。
2. 复用既有原生XAML几何/电量/主题测试和生产Board初始化、订阅、布局、停止恢复测试。
3. 编译包含实际生产Panel/Popup/Metrics代码的独立生命周期测试，记录编译输入SHA，以Explorer普通用户令牌运行。隐藏的自有窗口覆盖未初始化、部分初始化、完整初始化、cookie/PID已更换和原宿主窗口已销毁的清理路径；向自有窗口传递关闭、锁屏、休眠通知以及无效宿主检查，验证退出分支。反复启动/停止只读采样线程，并检查隐藏时不采样、不接受设备写入。
4. 将正式面板复制到本轮独立目录，校验精确SHA，再以真实Explorer普通用户令牌运行已有`--hidden-probe`。默认重复三轮，各自保存读取、关闭和四档DPI绘制结果；不在正式目录生成测试日志或渲染图。
5. 用有限时间读取原生宿主公布的面板cookie、PID、可见窗口和系统光标。只观察正常使用自然发生的事件；不为了制造样本移动鼠标或唤出面板。
6. 核对正式运行文件/配置是否保持、组件是否正常、独立测试进程是否退出。结果保存到唯一时间戳目录并更新`latest.json`，旧结果保留。

脚本串行运行，具备互斥与阶段超时。超时只结束本测试创建的确切进程树，不按同名进程批量终止。普通令牌探针另有45秒时限，失败通过其拥有的进程句柄清理子进程；最终扫描仅核对本轮唯一目录中的探针，不自动清理其他目录或正式进程。

## 结果如何解释

`AutomatedChecksPassed`只表示所列自动检查通过。离屏PNG来自真实绘制代码加固定样本，是布局检查介质，不是用户桌面截图；助手需查看输出图确认遮挡、裁切和间距，不能只数图片文件。设备探针只读，不证明实际音量/亮度写入或热点联网。三次启动/停止不是长期压力测试。

观察记录为`NotObserved`时，表示没有自然悬停样本，不能判定该交互通过。出现繁忙光标与面板活动重合仅提供相关证据，其他应用也可能产生繁忙指针；不能未经定位就归因于Dock。光标读取失败、定制光标或采样间隔也限制覆盖范围。

自动检查发现确定性问题时，助手依据日志修复实际相关模块，再复测失败项及受影响回归；通过既有构建、预检后按已授权的维护流程加载，保留回退。无样本或审美判断不触发盲目修改。实际桌面输入仍遵守用户当次许可限制，不以自动验收之名越过它。

生命周期测试中的宿主是自有隐藏窗口，锁屏/休眠是传给该窗口的通知，不能代替实际锁屏、睡眠恢复、Explorer重启或设备断连验收。句柄数按阶段记录以区分首次加载与逐轮累积，不以冷启动前后的差额直接断言泄漏；有限轮次中稳定也不能证明所有路径无泄漏。该测试在本机正常设备环境约束退出时限，不代表已注入或解决设备驱动永久阻塞。

退出消息测试需在限时内正常处理整个消息队列。单次筛选PeekMessage没有拿到WM_QUIT，不足以判断生产退出失败；首次扩大测试曾因此产生误判，已按正常消息循环修正。参考微软对[PostQuitMessage的延迟退出语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postquitmessage)与[WM_QUIT按队列状态生成](https://devblogs.microsoft.com/oldnewthing/20051104-33/?p=33453)的说明。原失败记录保留，未因此更改正式运行代码。
