# Windows 设置窗口大小恢复记录

日期：2026-10-11。本次是单个应用的本机窗口状态处理，没有修改或部署 Dock 程序。

## 现象与检查

用户反馈从所有入口打开 Windows“设置”都会回到偏小的普通窗口或最大化，并确认手动调整大小后此前也记不住。当前运行版本仍为包 0.8.15、后端 0.5.15，源码 0.8.16 未部署。

- 最初读到 Settings 的 ApplicationFrameWindow 处于最大化，普通窗口恢复矩形为 `[718,426,1927,1421]`，即 1209×995 物理像素。重新打开后的普通窗口与该记录一致，窗口 DPI 为 144。
- 快速设置定位同时限制 `ControlCenterWindow` 和 `ShellHost.exe` 路径；开始菜单限定 `StartMenuExperienceHost.exe`。生产包对应源码与仓库一致。完整设置由 `SystemSettings.exe` / `ApplicationFrameHost.exe` 承载，两者当次模块列表均未发现 LeanDock 组件。
- 静态检查未发现 Dock 改写完整设置的窗口大小或恢复记录；这不能排除尚未验证的间接影响，也不能证明用户先前的故障不存在。

## 实际处理与结果

1. 备份当前用户 AppModel 中仅 Settings 的 ApplicationFrame 分支。
2. 正常关闭设置后，只更新其 `Positions` 二进制值，写入一个屏幕内的普通窗口矩形，保留 `PreferredMinSize` 及其他数据。没有重置整个设置应用，没有调整显示缩放、工作区或安全设置。
3. 通过系统应用入口重新打开，确认能读到临时写入的 1800×1200 普通窗口。
4. 用户亲自再次调整、关闭和重开，确认“能保持刚调整的大小”。保存记录已变为用户的新矩形 `[458,139,2247,1496]`，即 1789×1357，与临时值不同。
5. 助手随后再次重新打开，读取到新的窗口句柄；`GetWindowPlacement` 和实际窗口矩形均与用户的新记录一致，`showCmd=1`、`flags=0`。Dock 控制器与 Explorer 没有重启。

结论：这次会话已验证手动调整后的保存与重开恢复正常。未复现并定位最初“手动调整后又丢失”的写入过程，不能把重新写入记录有效等同于已证明原记录损坏，也不能认定 Dock 是或不是最初诱因。重启登录、长期运行和多显示器尚未验证。

## 维护边界与本地材料

故障处理前的注册表备份、只读尺寸快照脚本及验证记录保留在本次工作区仓库之外的 `work/settings-window/`。恢复备份会恢复旧尺寸，应先正常关闭设置并确认没有需要保留的新尺寸，不要自动回滚。

临时只读观察最长运行 90 秒，已经结束。不要为这个结果增加常驻强制改窗逻辑，也不要将该机器的 `Positions` 值打包成通用 Dock 配置。若复发，应先记录用户实际调整、关闭、重开各阶段的窗口和保存值，再定位首次偏离的环节。
