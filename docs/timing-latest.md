# 0.5.6 时序审查

## 已修补的执行路径

- 开始菜单：移除控制程序中的 SHOW／UNCLOAKED → 30ms → SetWindowPos 和隐藏时恢复坐标。沿用已有 Start 组件，在本窗口 UI 线程的 WM_WINDOWPOSCHANGING 阶段改待提交坐标；与快速设置共用几何规则。可响应的隐藏宿主先接入，暂停的宿主等后续原生事件；没有增加位置轮询。
- 菜单发现与退出：先关闭事件入口，再解除挂钩和组件。移除了原有延迟定位消息与计时器，因此停用后没有这类排队移动。Start 状态通过当前宿主的只读属性与存活进程句柄核对，避免为读取状态等待挂起的 Start UI 线程。
- 智能隐藏：线程退出时显式取消并清零尚未触发的计时器。停止事件在创建线程前存在，线程先创建消息队列再检查停止标记；停止方同时发送唤醒消息，覆盖“停止发生在消息队列创建之前”的顺序。退出等待有上限，并允许必要的同步窗口回调完成；后端拒绝停用期间重入的启动／停止操作。排队的任务栏刷新携带代次，不能跨过 Stop／Start 生效。
- 媒体按钮：切换播放器和停用时先使旧操作代次失效，再取消异步请求。旧播放器的迟到结果不能释放新播放器正在使用的按钮状态，也不能继续占住按钮。
- Dock 边界：布尔就绪标记改为带版本的快照。读前、读后的版本必须相同且写入已完成，防止应用／托盘尺寸改变时拼出新旧混合的几何数据。

## 审查与验证边界

已有媒体标题请求和开始菜单布局回调具有代次检查；卡片回调使用弱引用，界面对象仍由所属 UI 线程处理。原生 Win+X 的参照控件路径保留，没有恢复事后移动菜单窗口的旧方案。触发角源码和配置沿用本机较新的设置，本次不改变其动作或延迟。

自动验证使用自有隐藏窗口和事件线程，不发送生产桌面鼠标或按键。包含实际窗口提交坐标、50 次线程启停一组、双线程 40,000 次几何发布、旧媒体命令迟到及其他既有回归。初版事件等待候选未通过反复退出测试，未部署；最终保留 GetMessage 消息循环，并补齐可靠的停止通知与有限等待。

程序化检查不等于用户界面的逐帧验收。真实开始菜单反复开关和点击、快速设置动态媒体高度、多显示器／DPI 切换、睡眠及登录仍应分别记录结果。冷启动宿主第一次被发现前，允许原生行为，不承诺未附加窗口也能提前定位。

本次检查期间，旧版 ShellHost 曾于 2026-10-08 21:22:30 更换进程，现有保护停止重复附加。所检查的 Application 1000／1001 事件没有对应错误；不足以确认退出原因。保留这项防止反复崩溃的保护，不把宿主换进程自动判定为崩溃或自动无限重试。

包版本 0.5.6，控制程序 0.3.3，Explorer 组件 0.4.5，Start 组件 0.1.3，快速设置位置组件 0.1.1。更新三个宿主内的组件前，先正常停止控制程序，按完整路径、会话、实际加载模块核对需要退出的宿主，再替换文件。正式部署使用带哈希验证的 0.5.5 备份和限时自动回退；配置不覆盖。具体自动与人工结果以 verification-latest.json 为准。
