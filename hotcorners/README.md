# 触发角配置

集成模块版本：1.0.3-integrated。仍使用同一隐藏控制进程和原始输入事件，不增加后台程序。

当前配置：左上锁屏需连续停留 500 毫秒；左下显示／恢复桌面、右下任务视图为零延迟；右上禁用。触发区仍是 3 个物理像素，触发后需移出 32 像素区域才能再次触发。

`DelayMs` 是四角的默认延迟。`TopLeftDelayMs`、`TopRightDelayMs`、`BottomLeftDelayMs`、`BottomRightDelayMs` 可分别覆盖，范围为 0–1500 毫秒。缺省继承 `DelayMs`，显式 0 表示立即触发。无效值会拒绝整个配置并保留此前有效设置。

进入有延迟的角落后才启动等待定时器，提前离开触发区会取消；再次进入重新计时，不累计短暂停留。零延迟角在输入事件中直接触发。拖拽、按键修饰、全屏抑制以及暂停／锁屏／显示器变化清理规则继续有效。Windows 忙碌时定时器可能稍后调度，但不能在设定时间前触发。

配置更新后使用部署目录的 `latest.ps1 -Action ReloadCorners`。管理器 `Status` 返回的 `HotCorners.cornerDelayMs` 是运行实例实际采用的各角延迟，不能只看磁盘配置。

源码维护入口是 `core/latest.h` 和 `../build/adapt-hotcorners-latest.py`；后者生成 `../src/hotcorners-latest.cpp`。不要只修改生成文件。`../tests/hotcorners-latest.ps1` 默认执行逻辑和配置测试，不接管生产输入、不提交动作；接入测试仍需显式指定 `-IncludeHosted`。

2026-10-08 的单角延迟变更已通过 66 项核心检查和 22 项配置检查。覆盖 499/500 毫秒边界、移开取消、重新计时、下方角立即触发、继承与显式零值、无效配置原子拒绝和状态回读。用户同日实际确认：“符合预期，下面两个角也正常”。此验收覆盖左上角短暂停留取消、停留半秒锁屏及下方两角正常，未扩大为多显示器或长期运行验证。

本机控制程序更新期间，普通停用／重新附加导致 Explorer 异常重建，已先恢复原版本，再以干净重载成功加载新控制程序；Explorer 和开始菜单 DLL 均保留原文件哈希。后续更新采用备份及干净重载流程，不反复尝试原地热重连。回退与本次部署记录保存在部署目录的 `hotcorners/change-latest.json`，原配置和 EXE 已备份。
