# 触发角配置

集成模块版本：1.0.14-integrated。仍使用同一隐藏控制进程和原始输入事件，不增加后台程序。

胶囊 0.9.3/0.9.4 补全开始菜单前台转接：识别受信系统路径的 StartMenuExperienceHost
与 SearchHost 顶层 CoreWindow，并区分 DWM cloak。返回桌面／Ctrl＋Alt＋Tab／任务视图触发时，
先关闭已打开的面板，再在面板实际隐藏并释放前台后提交原动作。搜索关闭后若露出
Start，至多再关闭一层，不重新计时。过渡等待上限
700 ms，仅此期间使用 15 ms 定时器；用户按键/拖拽、锁屏、停止、宿主失效或超时
会取消，不向其他窗口补发迟到动作；正常销毁的面板可以完成关闭。未打开面板时维持原事件路径。
日志 start-dismiss-request/complete/cancelled 只表明请求与状态，不代表用户界面验收。

当前配置：左上锁屏需连续停留 500 毫秒；左下显示／恢复桌面、右下应用切换器为零延迟；右上禁用。触发区仍是 3 个物理像素，触发后需移出 32 像素区域才能再次触发。

0.8.59 增加重复触发关闭：实际 Ctrl＋Alt＋Tab 已显示且为前台时，再次进入右下角发送一对 Esc 按下／释放；退出后下一次进入重新打开。移出 32 像素区域后才重新触发的原规则保留，停在角落不会连续开关。关闭前取消未消费的两项确认请求，并再次核对前台和可见标识；状态变化则放弃这一轮，不自动重试。状态 switcherToggle 分别记录打开、关闭请求与状态变化放弃次数；请求成功不是视觉关闭验收。

右下角使用 `BottomRight=app-switcher`：提交完整的 Ctrl+Alt+Tab 按下和释放序列，由 Windows 保持切换器显示，不模拟长期按住 Alt。0.8.49 在原生列表恰好两项且选中缩略图已经可调用时，自动执行该项的原生确认动作；其他数量或未能确认时继续显示切换器，可点击窗口，或用方向键及回车选择，Esc 取消。直接键盘调用 Ctrl+Alt+Tab 不产生此一次性请求。`task-view` 仍可用于原来的 Win+Tab 任务视图，两种动作分别保留。

两项判断读取系统实际 SwitchItemList，不用进程数量或任意顶层 HWND 估算。每次热角只发出一个 1.5 秒有效的一次性请求，由同一 Explorer 的可见切换器、当前前台线程和原生选择共同确认；提交失败、停止或超时即失效。消费请求后才调用缩略图，避免重入和迟到回调重复切换。没有额外的定时器、输入钩子、按键确认或后台程序。兼容性、真实动画和潜在的短暂列表闪现边界见 docs/switcher-style-latest.md。

0.8.48 同时检查组合键是否已被用户按住；注入仅部分成功时，只对已注入且未释放的键按相反顺序尝试释放。输入被系统阻止时记录失败，不将清理尝试当作成功，也不反复补按。自动测试不发送真实按键；切换器的显示、选择与取消须由实际操作验收。

`DelayMs` 是四角的默认延迟。`TopLeftDelayMs`、`TopRightDelayMs`、`BottomLeftDelayMs`、`BottomRightDelayMs` 可分别覆盖，范围为 0–1500 毫秒。缺省继承 `DelayMs`，显式 0 表示立即触发。无效值会拒绝整个配置并保留此前有效设置。

进入有延迟的角落后才启动等待定时器，提前离开触发区会取消；再次进入重新计时，不累计短暂停留。零延迟角在输入事件中直接触发。拖拽、按键修饰、全屏抑制以及暂停／锁屏／显示器变化清理规则继续有效。Windows 忙碌时定时器可能稍后调度，但不能在设定时间前触发。

全屏抑制只针对游戏（0.8.90 起）。`PauseOnFullscreen=1` 表示前台是全屏游戏时四角不响应；其他全屏应用（播放器、浏览器、终端等）照常触发。`PauseOnFullscreen=0` 则任何时候都触发。判断规则与 Dock 的全屏呼出共用 `../include/fullscreen-app-policy-latest.h`：独占全屏的 Direct3D 程序；可执行文件位于 `\steamapps\common\`、`\Epic Games\`、`\XboxGames\`、`\Riot Games\`、`\WeGameApps\`、`\HoYoPlay\games\`、`\GOG Galaxy\Games\`、`\GOG Games\`、`\Ubisoft Game Launcher\games\`、`\EA Games\` 之下；或文件名列在 `Games=`（分号分隔，不区分大小写，整名匹配）。无法读取进程路径时按游戏处理。`Games=` 随配置一起读取，配置被拒绝时保留上一份名单。状态里的 `blockReasons.fullscreen` 只计游戏造成的拦截，`fullscreenAppEntries` 记录全屏应用中被放行的进入次数。

配置更新后使用部署目录的 `latest.ps1 -Action ReloadCorners`。管理器 `Status` 返回的 `HotCorners.cornerDelayMs` 是运行实例实际采用的各角延迟，不能只看磁盘配置。

源码维护入口是 `core/latest.h`、`actions/latest.h` 和 `../build/adapt-hotcorners-latest.py`；后者生成 `../src/hotcorners-latest.cpp`。不要只修改生成文件。`../tests/hotcorners-latest.ps1` 默认执行逻辑和配置测试，不接管生产输入、不提交动作；接入测试仍需显式指定 `-IncludeHosted`。

更新器保留现场配置。安装支持 `app-switcher` 的新控制器后，再备份并只修改原配置的 `BottomRight`，执行 ReloadCorners 并核对实际动作。回退到 0.8.47 或更早版本前，先恢复原来的 `task-view` 配置并重载；旧版不能解析新动作名称。每次配置迁移另存变更前配置与运行读回，不用默认配置覆盖其他偏好。

2026-10-08 的单角延迟变更已通过 66 项核心检查和 22 项配置检查。覆盖 499/500 毫秒边界、移开取消、重新计时、下方角立即触发、继承与显式零值、无效配置原子拒绝和状态回读。用户同日实际确认：“符合预期，下面两个角也正常”。此验收覆盖左上角短暂停留取消、停留半秒锁屏及下方两角正常，未扩大为多显示器或长期运行验证。
