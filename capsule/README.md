# LeanDock 胶囊重构

本目录实现桌面 handoff 的 PLAN.md v1，源码版本 0.9.8。迁移前的 0.8.78
是独立的旧架构。构建完成、测试完成、部署完成、用户实际验收分别记录。
开发仓库的 capsule/verification-latest.json 保存最新证据，正式部署根目录
的 latest.json 保存安装回执；没有成功回执不得认为正式版已替换。

## 设计与行为

普通用户运行的原生 Win32 / Windows.UI.Composition 界面，加同一可执行文件
的看门狗进程。没有 Electron、WebView、.NET 或 Windhawk 运行依赖。
底边检测 20 毫秒一次；按用户最新要求恢复旧版已验收的比例：底板高 60 DIP、
圆角 30 DIP、底部间隔 4 DIP，大图标 40 DIP、按钮间距 52 DIP。宽度由内容决定，
空间不足时沿用旧版 52/48/44/40 的按钮宽度降档，图标同比缩放，信息区优先。
0.9.5 按用户选定的 A 版，把时间与日期合在 72×46 DIP 的短胶囊中：上行时间
18 DIP，下行日期 11 DIP，无星期；电量通过沿轮廓顺时针增长的细环表示。
环从顶部中心起算，内缩 1.6 DIP、线宽 1.4 DIP；满电闭合，0% 无彩色进度，
电量未知或无电池时只保留中性底环。低于 20% 用琥珀色，不高于 10% 用红色。
不常显独立百分比、充电图标或装饰填充；精确电量和充电/续航状态仍在详情中。
信息区悬停 400 毫秒显示详情。Win+T 固定显示，Esc 取消。
时间点击向核验过的真实 Explorer 发送公开 SC_TASKLIST 系统命令；不用 Win 键
输入模拟，不受前台应用输入完整性级别的那条限制。记录仅区分命令投递与失败，
不能把投递成功当作开始菜单已显示；实际点击结果另行验收。
0.9.1 的最大化应用下点击时间已获用户确认。0.9.2 移除该点击后的主动隐藏，
0.9.3 同时识别真实 Start 与 Search 宿主，以 DWM cloak 判断菜单的显示期，期间保持 Dock；菜单
关闭后恢复原隐藏规则。命令已发出但菜单未出现时，等待最多 1.5 秒，不永久锁住 Dock。
0.9.6 将悬停详情改为原生控制面板，宽度仍为 300 DIP。音量/亮度滑条直接
写入系统设备，扬声器单击静音/恢复；拖动音量到非零会解除静音。Wi-Fi/蓝牙
卡片主体直接开关对应无线设备，箭头分别进入系统网络选择和蓝牙设备设置。
无线权限只在真实操作时申请；拒绝、硬件禁用或设备缺失不会伪报已开启。
保留 CPU、内存（比例与已用/总量）、GPU、网速、磁盘、电池和托盘；没有媒体、
读不到温度或没有托盘内容时，相应空行收起。没有把 Windows 快速设置窗口嵌入
Dock；配对、网络选择等完整流程继续由系统处理。主信息键保持整体单击开 Start。

0.9.6 的音量、亮度、静音/恢复和拖动保持显示已有用户实际验收。0.9.8 在相同
宽度的面板保留第二行“深色主题 / 移动热点”；主体切换，右箭头打开对应系统
设置。主 Dock 短胶囊尺寸和行为不变。热点使用公开 WinRT 接口、Windows 当前
Internet 连接及已有热点配置，开启后显示连接设备数；不修改名称、密码、频段、
Mihomo、ICS 服务配置或驱动。接口失败显示错误，切换过程中阻止重复请求；
隐藏/退出仅取消等待，不主动关闭已开启的热点。系统仍可能完成已发出的请求，
再次显示时读回实际状态，不将取消等待理解为撤销系统动作。

用户纠正了 0.9.7 对“夜间模式”的误解：要的是旧版 Dock 的深色/浅色主题。
0.9.8 直接调用原有固定路径控制器的 --theme dark/light 短时工作进程，保持
原行为：应用/系统配色、Windows 内置 dark/aero 主题及对应 img19/img0 壁纸。
右箭头进入 Windows 主题设置。0.9.7 的暖色护眼代码与许可证移入独立历史
归档，不再编译或打包；当前按钮不读写 Night Light 的 CloudStore 状态。
更新不自动修改用户当前主题、壁纸、色温或定时。

主题控制仍由旧工作进程承担私有 IThemeManager 调用、themeui.dll 哈希校验、
跨入口互斥、失败条件回退和完整广播；不在新 UI 内重写这些机制。新适配器
验证既有控制器和系统组件哈希，普通权限隐藏启动，异步等待退出，并核对
退出码与实际配色；混合配色单独显示。隐藏面板允许已提交的切换完成，卸载
或 30 秒等待超时仅释放等待句柄、不强杀正在应用主题的进程；旧互斥量继续
阻止重叠请求。超时不伪报成功，也不能保证异常系统调用会按时退出。
未来重建原控制器必须同步核验 theme-control-latest.h 的控制器哈希。旧原生
QuickTheme 卡片未挂上不阻挡新面板直接调用主题工作进程；不宣称旧卡片已修复。
2026-10-22 用户确认“深浅切换和 Dock 恢复都正常”，旧主题与对应壁纸往返、Dock 配色恢复已验收；热点开关和客户端联网仍待实际使用验收。

系统控制由原有 Metrics 线程处理，没有新增常驻程序或采样线程；主题只在
真实点击时按原版启动短时工作进程。CPU 仍一秒
采样一次；详情显示期间设备状态每秒读取，隐藏后停止详情/设备读取。无线枚举
只在打开或设备变更时进行；异步操作待完成期间 50ms 查询状态，完成即停止。
滑条 75ms 限流并按控件合并待执行命令，松手立即提交末值，执行后读回真实值。
拖动期间捕获鼠标并保持 Dock/面板，丢失捕获、隐藏和卸载时释放；后台处理不
调用任何桌面输入模拟。亮度使用内部屏幕的 WMI 实例，不保证外接屏 DDC/CI。
WMI 枚举和方法结果有显式超时，普通 COM 调用取消用于卸载；服务失联情况下
的最坏退出时长没有实测保证。无线请求有超时和取消，迟到结果不持有 UI 指针。

电量改变只重画信息键；隐藏时推迟到显示再刷新，不重建应用列表。
时间沿用现有分钟刷新，电量沿用系统通知。
尺寸、命中区域、详情锚点和几何协议继续共用当前布局。单击开始菜单、
悬停详情、右键菜单沿用已存在的入口；本轮没有修改触发角、切换器、
开始菜单/搜索定位，也没有恢复应用启动自动最大化。

应用图标复用旧版 icon-optics-latest.h 的透明边界补偿与视觉居中，放大上限
1.35 倍。0.9.1 的 120 像素取图与中间绘制链未通过用户清晰度验收；0.9.2
请求 Shell 的 256 像素资源档，记录实际返回大小，用 WIC Fant 在补偿后的最终
物理尺寸缩图，再按像素对齐上传，避免静止时第二次缩放。没有替换应用图案、
强制裁圆角或加入锐化滤镜；阴影与原始比例保留。移出列表的缓存及时释放。
0.9.3 修正 Shell ICONONLY 位图的 alpha 声明：已核验栖页返回直通 alpha，
旧版误当成预乘值会放大透明边缘的白色 RGB。现在明确导入直通 alpha，
最终栅格转换时只预乘一次；真实资源及透明/半透明测试另外校验，不修改应用文件。
菜单、详情与几何协议共用
底板尺寸，避免外观变大而点击区域、隐藏位移或面板锚点仍停在旧位置。

应用从原 Windows 固定列表和实际窗口取得。固定列表仍由 Windows 管理，
没有另建一份副本。原系统修改固定列表后，本程序通过注册表事件刷新。
本机原生写入测试返回成功但列表不变，用户同意难以完成的同步写入不强做，
因此固定/取消固定项暂灰显，拖动排序未开放。不会假报保存成功。

用户已明确选择“保留这些旧功能，只替换 Dock 界面”。现有 Highest 登录任务
继续运行配套控制器，管理触发角、Ctrl＋Alt＋Tab 定制、紧凑开始菜单、
快速设置和底边兼容。控制器按微软公开方案，以同用户、同会话、普通权限的
真实 Explorer 作为创建父进程，启动新界面，
在放行前检查真实子进程的用户、会话和 Medium 完整性；失败则不启动界面。
界面与看门狗仍拒绝高权限运行，从界面启动的普通应用不会继承管理员令牌。

companion-adapt-latest.py 只在隔离构建目录适配当前原生源码：样式引擎仅
加载切换器规则，旧 Dock 样式、原生图标补偿、卡片、托盘重排和底边监听
不启动。保留原有模块哈希门控、钩子停用、属性恢复和宿主重接责任。
新界面发布现有几何协议，供保留的开始菜单和快速设置 DLL 继续定位。
Explorer 的真实任务栏按进程路径核验，避免误认新托盘接收器的同名窗口。
Ctrl＋Alt＋Tab 的真实界面与点击仍需本轮人工验收，不能只用后台 ready 代替。
触发角模块 1.0.14 在开始菜单或搜索为前台时，先发一对 Esc，待面板实际隐藏并释放
前台后执行原动作。搜索关闭后若露出 Start，至多再关闭一层；总等待上限仍为
700 ms，仅该过渡期间启用短时定时器。用户按键、拖拽、锁屏、宿主身份变化、
超时或停止均取消；正常销毁的窗口可完成关闭。没有面板时保持原调用路径。
开始菜单和搜索窗口统一在原生 WM_WINDOWPOSCHANGING 提交前放在 Dock 上方，
保留 8 DIP 间隔。必要时缩短过高的原生宿主，继续使用原生响应布局和滚动；
不在显示后延时搬窗。Search 适配复用 Quick 的线程钩子、子类、所有权与退出恢复，
不初始化 Start 的 XAML 模板，不改变搜索内容。它独立校验当前 SearchHost.exe 哈希，
更新不兼容时保留系统位置。Start 与 Search 共用 start/latest.dll，但状态各在自己的进程内。
0.9.3 的首次接入核验发现 Search 为 AppContainer，读取 DLL 和直接打开控制器
均返回拒绝访问。0.9.4 只给经核验的 CBS 搜索包授予 start/latest.dll 的读取/执行，
不扩展目录权限；原文件 DACL 纳入事务与回退。控制器只向精确搜索进程交付
QUERY_LIMITED_INFORMATION | SYNCHRONIZE 句柄，宿主核验精确路径、存活状态以及当前桌面的
控制器窗口所属 PID，再复制用于退出等待；控制器在交付前校验 Search 的会话。
实测 ProcessIdToSessionId 在 Search 受限令牌下仍会重新申请访问高权限控制器并返回错误 5，
因此不再从宿主调用这一按 PID 查询路径；没有通过放宽进程权限解决。
不改变进程 DACL、不授予内存读写/终止权限、不放宽系统防护或全局消息过滤。
同步请求完成后撤回临时句柄；超时不抢先关闭可能被迟到回调使用的句柄，停止
该 PID 的重试，至多一个只读临时句柄留到宿主退出。自有等待句柄正常卸载时释放。
SearchPosition 现在独立进入维护状态和恢复要求；曾经正常接入的搜索定位不能被
仅 UI ready 掩盖。未知系统哈希保留系统默认位置并报告降级，不绕过兼容门控。
ChatGPT 提权辅助程序是另一套部署，本次不改它。

## 构建与检验

使用仓库既有独立 Clang/MinGW/C++/WinRT 工具链和 Windows SDK 10.0.26100.0：

```powershell
pwsh -NoProfile -File capsule/build-latest.ps1
pwsh -NoProfile -File capsule/tests-latest.ps1
```

若当前命令窗口是管理员，改用 capsule/test-user-latest.ps1 运行检查；
它按经过核验的 Explorer 普通权限创建测试进程，避免用提权环境代替真实 UI 环境。

输出 capsule/build/latest.exe。按 asInvoker 清单运行；正式 UI 和看门狗拒绝
高完整性令牌。原计划任务的名称、路径和 Highest 级别均保留，启动配套控制器；
控制器验证 Explorer 与实际子进程的普通用户令牌后启动界面，不能把任务直接改为 Limited。

检验分层：

| 入口 | 实际做的事 | 不代表什么 |
|---|---|---|
| tests-latest.ps1 | 策略、隐藏合成初始化、协议、原生列表、数据、真实子进程重试 | 不代替用户点击验收 |
| --visual-probe | 在自有棋盘格窗口上显示自有胶囊/详情，改变背景并保存其范围图像 | 不读取其他窗口内容，不验证全部用户交互 |
| --native-tray-probe | 短时接收并转发真实通知注册，加入/删除自己的测试图标，恢复原接收器 | 不点击用户的托盘图标 |
| --idle-probe | 隐藏合成树、20 ms 光标逻辑和 1 s CPU 数据的 30 秒测量 | 未包括原生托盘接管、不是新旧总内存比较 |
| --icons-probe | 从真实应用资源导出源图和最终栅格，检查五档 DPI 的 surface 大小与像素映射 | 从不显示测试窗口，不代替真实 Dock 清晰度与动画验收 |
| --guard-probe | 同一守护循环启动四个真实失败子进程，耗尽三次重试 | 用计数替代真实任务栏恢复，不改系统任务栏 |

所有诊断都有外部超时；超时只结束精确 PID 的自有测试进程。不得用
latest.exe 名称批量结束程序。不得用桌面输入自动化补充人工验收。
可见测试会核对输入桌面；锁屏时返回明确的待验收状态，不把锁屏背景保存为
界面通过证据。用户已授权离席时继续完成加载，因此这种已识别状态可随安装包
保留为 PendingInteractiveDesktop；其他测试失败仍阻止打包和加载。
用户正在使用电脑时，使用 test-user-latest.ps1 -DeferVisualAcceptance，
不显示额外测试窗口或操作桌面输入。此时打包明确记录 PendingUserAcceptance
及原因，普通权限技术检查仍全部执行；这不是可见效果已通过的声明。
0.9.5 新增 --time-key-probe：直接调用正式绘图函数，在私有 GPU 位图中生成
100/125/150/175/200% 五档缩放、三种底色与六种电量状态，共 90 个样本。
输出 build/time-key-probe；不截图桌面、不显示窗口、不模拟输入。
同时检查真实 D2D 描边边界与周长比例、文字宽度和电量未知值。
该检查与用户正常唤出 Dock 后的实际观感、点击验收分开记录。

## 安装与恢复

package-latest.ps1 生成带逐文件 SHA-256 的独立包。维护入口继续采用
Update/ValidateOnly/Rollback 事务，胶囊适配器位于
maintenance/capsule-latest.ps1，复用原有路径、哈希、签名和回退校验。

首次迁移验证现用 Dock、原始计划任务、全部回退运行文件和应用控制。
停止旧控制器会连带停止旧开始菜单、触发角与快速设置模块；不能按普通 DLL
更新处理。事务保留配置和任务 XML，精确核对 Explorer 后重载，仅在新 UI、
托盘、守护进程、普通权限，以及更新前八项组件条件全部恢复后提交。
计划任务不改写。任何失败回滚原文件并恢复更新前要求可用的组件；
独立维护观察进程处理维护进程异常退出。原配置、完整旧 DLL 集和任务 XML
保留在回退集中。相同内容的宿主 DLL 不强行覆盖已映射文件。
原生宿主 DLL 确实变化时，沿用原维护器的精确进程释放流程：先停止控制器，
只结束已加载该 DLL 且路径、会话、启动时间均符合记录的 Start/Search/Quick 宿主，
再换文件。回退也执行同一释放检查，避免停用后仍映射的 DLL 阻塞覆盖。

同一事务也支持胶囊架构后续更新，更新前必须确认现用界面和全部配套组件健康。
Stop 会恢复系统任务栏，但 XAML 和跳板仍安全地驻留在 Explorer 中。
真实 Stop/Start 检查发现原地再次接入 XAML 会报 E_UNEXPECTED；因此 Start
在检测到这类已停止或失败的旧宿主时，采用既有的精确 Explorer 重载流程，
随后核对上次成功回执要求保留的所有组件。健康实例的重复 Start 不重载。
安装目录内的 LeanDock.lnk 可直接双击启动，调用上述恢复入口；未在桌面或
开始菜单增加快捷方式。它本身按普通权限运行，再使用原有已授权计划任务
启动配套控制器。关闭胶囊界面后，保留功能仍运行，再次打开可用此入口。

新运行时保存原 AppBar 自动隐藏状态。正常退出、会话结束、初始化错误都恢复
系统任务栏。看门狗一分钟最多重启三次；恢复预算耗尽则退出并保留原生任务栏。
UI 监测守护进程死亡；设备丢失使 UI 有界退出，由守护进程重建。

## 关键限制与剩余验收

- 当前已实读的 QuickTheme 为 active=true，但 rootReady/tileInstalled/buttonReady=false、
  failures=1；这是本轮前已存在的限制。快速设置定位组件与主题按钮功能分别核对，
  不把旧的 active 标记解释为主题按钮已经恢复。
- 原生固定列表 COM 只对核验的 shell32.dll 哈希开放。Windows 更新后不猜测
