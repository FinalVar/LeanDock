# LeanDock 0.9.2 交接

2026-10-21 已通过既有 Update 流程安装 0.9.2。本次只修改胶囊图标绘制、时间点击后与 Start 的显示关系，以及 Start 打开时的触发角转接；保留新胶囊结构、信息区、普通用户权限和旧配套功能。

用户已确认 0.9.1 在最大化应用前点击时间能打开开始菜单，同时反馈图标模糊且与之前不同、打开 Start 时 Dock 不应隐藏、Start 打开时触发角失效。不能把上一版的尺寸检查当成清晰度已通过。

本版技术检查和部署已通过，真实图标清晰度、Start 打开期间 Dock 保持及两边触发角尚待用户正常使用验收。没有运行可见测试窗口、控制用户鼠标键盘或切换应用来代替验收。

## 证据与本次改动

### 图标

上一版实际返回的资源为 120×120，而非假定的 32 像素图；另外核实当前应用可返回 256×256。旧链会先在按 DIP 取整的中间表面上缩图，再经过合成器的尺寸与小数像素映射；这会引入额外采样，但没有当前桌面截图用于分离各因素的视觉贡献。

新链继续由 Shell 返回应用自己的图标，请求 256 像素资源档且不设置 SCALEUP。直接复用旧 icon-optics 的 alpha 边界补偿、1.35 倍上限和居中，不替换图案、锐化或统一裁圆角。WIC Fant 只在最终补偿后的物理尺寸缩图，表面 1:1 上传、静止位置对齐物理像素。显示框仍是 40 DIP、按钮间距 52 DIP，底板 60 DIP、圆角 30 DIP、底部间隔 4 DIP；拥挤时保留旧降档规则。退出列表的图标缓存及时释放。

普通权限的隐藏测试使用实际六个应用，源图均 256×256；100/125/150/175/200% 共 30 行实际 Composition surface 与像素映射检查通过。150% 的补偿后画布分别为 60、72、60、64、72、60 像素；完整源图和最终栅格保存于 build/icon-probe，只包含图标资源，不含用户桌面或窗口内容。该结果不等于实屏清晰度验收。

### Start 显示期与 Dock

保留用户已确认有效的 SC_TASKLIST 入口。删除命令成功后主动 hide 的调用。只按受信系统路径的 StartMenuExperienceHost 顶层 CoreWindow 判断身份，并同时检查可见与 DWM cloak；现场确认关闭后的 Start 仍有 WS_VISIBLE，不能只用这个标志判断。

时间点击后等待最多 1.5 秒让 Start 打开；一旦观察到它实际显示，就保持 Dock，菜单关闭后恢复原 500 ms 隐藏规则。没有打开成功时不会永久钉住 Dock。复用已有 20 ms 输入循环，没有新增常驻进程或单独定时轮询。Start 显示时不抢先吞掉用于关闭菜单的 Esc，也不弹出悬停详情。

### Start 打开时的触发角

原故障缺少完整输入轨迹；读取到的历史 fullscreen 阻止项属于 LockApp，不是 Start，不能宣称已经证明是全屏误判。新转接逻辑只针对真实前台 Start：先发一对 Esc，待 Start 实际隐藏并释放前台后，再执行原来的返回桌面或完整 Ctrl＋Alt＋Tab。最多 700 ms，仅此阶段启用短时定时器；检测到持有按键、拖拽、锁屏、宿主失效、停止或超时即取消。没有 Start 时沿用原调用路径；真正全屏应用的保护规则保留。

实现放在 hotcorners/start-menu，修改 build/adapt-hotcorners-latest.py 后重新生成原源文件；没有只改构建副本。模块状态版本为 1.0.13-integrated。start-dismiss-request、start-dismiss-complete、start-dismiss-cancelled 等日志区分请求与转接结果，不能以 SendInput 返回条数替代 UI 验收。
