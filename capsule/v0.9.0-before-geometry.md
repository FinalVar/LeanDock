# LeanDock 胶囊重构交接报告

## 1. 当前结论

2026-10-21，0.9.0 胶囊架构已正式安装。新界面、托盘接收和普通用户守护进程
已运行，旧控制器继续保留触发角、Ctrl＋Alt＋Tab 定制、开始菜单紧凑排列、
快速设置和底边兼容。正式安装位置、登录任务及用户配置未改名或迁移。

后台就绪、安装与恢复检查已通过。用户目前处于锁屏会话，本轮没有完成真实
外观、点击、动画或手势验收；不得把旧版本的用户反馈移用为新版通过。
本报告配套的 verification-latest.json 和 build/deployment-after-latest.json
记录精确时间、哈希、进程与未验证项；回执中的 PID 只是当时快照。

## 2. 已确认的需求与实际实现

需求来源是桌面 handoff/PLAN.md v1，已保存于 docs/capsule-handoff。
prototype.html 仅作外观和动画参考。后续用户答复覆盖早期未定事项：

- 只替换 Dock 界面，保留触发角、Ctrl＋Alt＋Tab 和紧凑开始菜单等旧功能。
- 固定应用最好与 Windows 同步；原生写入难以实现时可以暂不实现。
- 用户离席也继续工作；常规构建和预检通过后允许加载及必要的 Explorer 重载。
- 不操作鼠标、键盘、用户窗口焦点，不更改防护设置。

胶囊按 44 DIP 高、离底 8 DIP、应用图标 30 DIP、间隔 8 DIP 实现。
底边 2 个物理像素唤出；92 DIP 底部带保持展开，离开 500 ms 后收起。
Win+T 固定显示，再次按下或 Esc、外部点击取消。信息区显示日期、电量和时间，
悬停 400 ms 展开详情；时间左键调用开始菜单，右键打开交接指定的自绘菜单。
详情使用真实 CPU、内存、GPU、网络、磁盘、音量、电池和媒体数据，托盘集中
于详情内。温度不可读取时显示缺失符号，没有随机数或假实时数据。

应用读取 Windows 固定列表及现有窗口，按 AUMID、可执行文件路径归组。
固定列表及顺序仍只由 Windows 保存；监听系统列表变化进行刷新。
本机 IPinnedList3 写入测试出现返回成功但列表不变，故固定/取消固定暂禁用，
拖动排序未开放，没有建立另一份存储或假报成功。

这是原生 Win32 / Windows.UI.Composition 界面，不增加 Electron、WebView
或 Windhawk 运行依赖。材质是公开 HostBackdropBrush 实时背景模糊，
没有实现透镜折射，不能称为完整 Liquid Glass。

## 3. 运行结构与复用责任

原有 Highest 登录任务仍启动正式根目录 latest.exe。它是配套控制器，
保留成熟的宿主校验、加载、停止、属性恢复和原功能。新 UI 和守护进程位于
capsule/latest.exe，真实进程令牌验证为普通用户、Medium 完整性。
因此用户从新 UI 启动的普通应用不会继承配套控制器的管理员令牌。

companion-adapt-latest.py 在独立构建目录适配旧源码，不直接改写原生生成物。
新后端仅启用切换器样式和 AppBar 兼容；旧 Dock 样式、图标补偿、卡片、
托盘重排、隐藏和底边唤出模块不再初始化，避免两套界面争用任务栏。
新 UI 发布既有几何协议，未改动的 Start 和 Quick Settings DLL 继续使用。

托盘接收、转发及回调移植自 ManagedShell 的固定提交，保留 GUID、版本化消息、
图标所有权、原接收器转发与 Explorer 重建责任。作者、许可、版本及本地差异
见 NOTICE.md 和 licenses，不能把本地 Win32 实现称为原样复用上游显示层。

## 4. 已完成验证与发现的修复

### 4.1 构建、协议与数据

- 55 项显示策略检查通过；隐藏合成树、背景画刷、几何和动画对象初始化通过。
- 25 项托盘协议检查通过；真实通知图标加入、版本声明、接收、删除及原接收器
  恢复通过。没有自动点击第三方托盘图标。
- 应用枚举读取到原固定应用与实际窗口；原生固定列表二进制哈希保持不变。
- CPU、内存、GPU、网络、电池等数据读取通过；详情隐藏后重采样计数不再增加。
  这不等于整个程序无轮询，底边检测仍每 20 ms 执行。
- 守护器用真实失败子进程验证四次启动、三次重试预算以及五次恢复分支。
  该隔离试验的任务栏恢复使用替身计数，真实恢复另见下一节。
- 原维护检查 51 项及本轮维护适配检查 15 项通过。后者覆盖文件路径、哈希、
  完整回退载荷、禁止改配置、已映射同内容文件免写，以及五种启动恢复分支。

### 4.2 权限与部署

TokenLinkedToken 在本机实测只是 SecurityIdentification 类型的模拟令牌，
不能直接用于 CreateProcessWithTokenW / CreateProcessAsUserW。
采用微软公开的 Explorer 创建父进程属性方案：验证真实 Explorer 的路径、
用户、会话和普通权限，挂起创建固定路径子进程，核对真实子令牌后才恢复线程。
没有建立任意命令执行接口、启用额外系统权限或修改防护。

安装包逐文件核对，原 latest.ini、hotcorners/latest.ini、Start DLL 和
Quick Settings DLL 未改变；NativeTaskbarDock 计划任务 XML 和原生固定列表
均与更新前一致。新版 UI、守护器、控制器分别检查了实际令牌和精确进程路径。

### 4.3 退出与重新启动

首次真实 Stop/Start 发现：旧 XAML 组件停止后仍留在同一 Explorer 中，
原地再次接入返回 0x8000FFFF，UI 虽已启动但配套组件不完整。
该次测试不算通过，错误证据保留在日志和本轮验证记录中。

修正后的 Start 检测已停止或失败的驻留后端，使用现有的精确 Explorer
重载流程，核对上次成功回执要求的全部八项组件条件。
健康状态重复 Start 不重载；干净的首次登录也不重载 Explorer。

修正后实际检查通过：控制器、UI 和守护器退出，原生任务栏窗口恢复，
AppBar 状态恢复到之前的 1，胶囊几何所有权被清除；重新启动后八项后台条件
全部恢复。开始菜单曾发生一次初始化重试，随后恢复；没有掩盖该计数。
Quick Settings 的未展开按钮状态不作为真实按钮验收。

## 5. 维护和回退

正式目录仍是：
`C:\Users\x\Documents\Codex\Tools\NativeTaskbarDock`

日常手动启动可双击该目录内 LeanDock.lnk。入口隐藏运行统一 Start 流程，
没有在桌面或开始菜单添加快捷方式。关闭胶囊后再打开也走此路径。
登录自启继续使用原任务，未增加另一份自启。

维护调用示例：

```powershell
& 'C:\Program Files\PowerShell\7\pwsh.exe' -NoProfile -File `
  'C:\Users\x\Documents\Codex\Tools\NativeTaskbarDock\latest.ps1' -Action Status
```

正式 latest.ps1 提供 Status、Start、Stop、Update、Rollback 和原触发角控制。
Update 使用独立安装包、逐文件哈希、配置保护、事务副本及失败恢复。
后续胶囊更新和首次迁移均已支持；更新前必须健康。
Stop 会恢复系统任务栏，同时停止配套控制器；菜单中的退出只退出胶囊界面。

第一次迁移的完整旧架构回退集是：
`backups\capsule-20261021-020020`

其中保留原 0.8.78 运行文件、配置保护哈希、旧回执和任务 XML。
当前 latest.json 的 Backup 是最近一次更新的前一版本，可能仍为 0.9.0；
**要整体回退到旧 Dock 必须明确选择上述第一次迁移回退集**。
回退前执行 ValidateOnly，确认所有原文件哈希及现有防护策略允许；
不能仅凭备份目录存在宣称实际回滚已执行。本轮未执行完整旧版回退。

已新增与修改的源代码仍在当前仓库中，未提交或推送。
仓库在本轮前已有大量修改，不把它们认作本轮产出，也不做重置或清理。
独立复核脚本位于当前任务 work/capsule-refactor-20261020/
verify-deployment-latest.ps1；加 IncludeLifecycle 会真正停止/恢复 Dock 和
重载所需 Explorer，不是只读选项。
